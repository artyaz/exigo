## Idea echoed
- **Title:** Accessibility-transcript render as the loop's only honest eye
- **Description:** Render each component to its accessibility transcript (heading order, landmark labels, accessible control names, reading order) derived from JSX/DOM and review *that text*; server-render React to per-state "contact sheet" (loading/empty/error/populated/focus-visible) stacked in one artifact and audit which states exist.
- **Riskiest assumption:** A11y transcript carries enough perceptual signal to catch real usability regressions — structural/semantic text is a valid proxy for a meaningful subset of UX quality.
- **Warrant:** The loop's native medium is language; encoding UI as language plays to its strength rather than faking sight.

## Steelman (1 paragraph)
The loop has no eyes and cannot get any (no Playwright/axe/Storybook — confirmed `package.json`). Rather than hallucinate pixels, this renders UI into the one modality the loop is genuinely good at: text. An accessibility transcript is not arbitrary — it is a spec-defined serialization (roles, accessible names, reading order) that maps to what a screen-reader user actually perceives, so a whole disability-cohort of UX is covered *natively*. The per-state contact sheet reframes the highest-value finding as an *audit of absence*: "does an empty/error/loading state exist at all?" is answerable from source with zero rendering fidelity, and missing-state bugs are common and high-impact. Even a lossy transcript beats the status quo of a blind loop.

## Toulmin decomposition
- **Claim:** A JSX/DOM-derived accessibility transcript is a usable perceptual substrate for the loop to review a meaningful subset of UX quality.
- **Grounds:** (1) The a11y tree/name computation is spec-defined and derived from DOM [1]. (2) BUT it is computed from *rendered DOM + CSS*: `display:none`/`visibility:hidden`/`content-visibility:hidden` remove nodes from the tree and from name computation [1][2][4]; static JSX has Tailwind class strings but no computed layout. (3) `renderToString` produces "initial non-interactive HTML," runs no effects, and renders Suspense fallbacks instead of awaited data [3]. (4) Repo has NO DOM env (vitest `environment:'node'`, no jsdom/happy-dom/RTL — `vitest.config.ts:6`) and 41/107 `_components` files are `"use client"` with hooks/Convex/framer-motion (`TestChatSidebar.tsx:1-25`). (5) Empirically, automated a11y catches ~57% of issues *by volume* but that is dominated by Contrast (30% of all issues, 83% auto) [5] — a pure-pixel property the transcript renders invisible; focus-visible & meaningful-sequence are 0% automatable [5].
- **Warrant:** If UX quality that matters is representable as role/name/order text, a transcript is a faithful proxy.
- **Backing:** ACCNAME 1.2 [1]; WAI ACT examples [2]; React docs [3]; Deque coverage report [5]; Karl Groves WCAG-testability tables [5b].
- **Qualifier:** Holds *only* for structural/semantic defects (Name-Role-Value 4.1.2 ≈54% auto; Info-and-Relationships 1.3.1 ≈45% auto [5]) and for state-existence audits — NOT for contrast, spacing, hierarchy salience, affordance, or focus appearance.
- **Rebuttal:** The tree is genuinely CSS-dependent [1][2][4] and effects/data are absent under `renderToString` [3], so a *static* derivation yields a partly-wrong tree; and the marketing framing "catch real usability regressions / meaningful subset of UX quality" over-claims against [5].

## Falsification attempt
- **Falsifier proposed (refined):** "If (a) the a11y transcript is insensitive to the defects UX review must catch (two materially different screens serialize near-identically), AND (b) a *static* JSX derivation cannot even produce an accurate tree without computed CSS + run effects, then the transcript is not a usable substrate."
- **Falsifier tested via:**
  - Repo greps: `div` 524 vs all semantic elements ~193 (2.7:1); only ~40 total `aria-*`/`role=` across the whole product surface → most components serialize to near-empty transcripts, so (a) is largely CONFIRMED for THIS repo. `AuthLayout` (`auth-ui.tsx:25-40`) is pure `<div>` + one `<h1>` → transcript ≈ the title only.
  - `vitest.config.ts:6` `environment:'node'`, no jsdom/RTL; `TestChatSidebar.tsx:1-6` `"use client"`+`useQuery(convex)`+effects → populated/error states unreachable under `renderToString` (no effects, data suspends [3]) → (b) CONFIRMED.
  - Spec [1][2][4]: CSS `display/visibility/content-visibility` and `aria-hidden` alter the tree; Tailwind `hidden`/`sr-only` appear 17× in `src/app/` → static derivation mis-serializes exactly those nodes.
  - Counter-evidence (partial refutation): 43 empty/error strings + `role="status"` (`ExerciseShell.tsx:117`) DO serialize → the *state-existence audit* sub-claim survives.
- **Outcome:** Falsifier substantially CONFIRMED for the strong claim ("perceptual substrate for UX quality"); REFUTED for the narrow claim ("static structural-absence audit").

## Position-swap reconciliation
- **Supporter reading:** [5] shows automation catches the majority of real issues by volume; Name-Role-Value + Info-Relationships are exactly what a transcript encodes; the state-absence audit needs no fidelity and finds real bugs.
- **Detractor reading:** The 57% is carried by Contrast/Non-text-Contrast/Use-of-Color — pixel properties invisible to a transcript [5]; the tree is CSS+runtime-dependent [1][3], and this repo has neither a DOM env nor render infra nor a11y-rich markup, so the transcript is both *inaccurate* (static) and *thin* (div-soup).
- **Reconciliation:** Detractor is better supported by the evidence *actually fetched*. The idea's technical premise ("derived from JSX/DOM" statically) is refuted by [1][3] and repo state; the sweeping value claim is refuted by [5]. What survives is a *narrower, real* tool — an audit of which states exist + a semantic-structure lint — not "the loop's honest eye" for UX quality.

## Verdict
- **Verdict:** INCONCLUSIVE
- **Confidence:** 0.7
- **Justification:** The strong form (a11y transcript as a perceptual substrate for UX quality) is refuted: contrast/spacing/hierarchy/focus-appearance are invisible to it and it needs computed CSS + run effects it won't have here. But a narrowed, genuinely valuable core survives — a source-level audit of state-existence (loading/empty/error) plus structural/semantic linting — which is testable and repo-feasible. Per brief, an idea that is neither cleanly grounded nor cleanly dead defaults to INCONCLUSIVE, not ADVANCE.
