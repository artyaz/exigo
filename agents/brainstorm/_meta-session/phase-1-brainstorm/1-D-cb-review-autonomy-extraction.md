# 1-D — cb-review Autonomy Extraction

## What cb-review is

`agents/cd-review/LOOP.md` (643 lines) defines a continuous, autonomous **hostile audit → brainstorm → fix → verify → record** loop for the Exigo codebase. It runs on two agent layers: a thin **launcher** (user-triggered, peer-process spawner) and an autonomous **day-scope agent** (no human in the loop, ~300k–350k context budget) that orchestrates three strict waves — A (audit, reviewers only, no children), B (brainstorm, decision packages only, no product edits), C (fix, surgical, disjoint file ownership) — consolidates into a master pack, ships via `develop → main` + CodeRabbit 5m/10m iteration, and writes a thin status contract (`day-status.json` + `RECORD.md` "Stopped at") so a cold launcher can resume. Dated run folders (`YYYY-MM-DD/`) hold all artifacts; `LOOP.md` is the single source of truth; nothing canonical lives at repo root.

## Item-by-item extraction

### 1. Launcher vs day-scope agent split (§0.5)

- **cb-review:** Two-layer split. The **launcher** (L-1) is a user-triggered, thin interactive session whose only jobs are: (a) find the latest `agents/cd-review/YYYY-MM-DD/`, (b) read `RECORD.md` + `day-status.json` only enough to know remaining work, (c) size a ~300k–350k-token chunk, (d) spawn a **separate** `grok` CLI process with an explicit day-scope brief, (e) background it, (f) poll **only** `day-status.json` + `RECORD.md` "Stopped at" (never the worker's full session JSONL), (g) re-wake the worker with a resume brief if it exits or stalls before scope is closed, repeat until scope complete or user cancels. The **day-scope agent** (L0) is spawned (not subagent'd) by the launcher, runs autonomously with no human in the loop, owns a large scoped chunk, dispatches Wave A/B/C subagents (in-process), consolidates, verifies, ships via §10.2, and updates `RECORD.md` + `day-status.json` after every material step.
- **Reuse verbatim.** This split is the load-bearing autonomy pattern. The launcher never becomes the worker; the worker never waits on the launcher.
- **Adaptation for brainstorming loop:** Zero structural change. Only the spawn-prompt content changes: scope is "one cycle = D1→C1→D2→C2→vote" rather than "Wave A→B→C→ship". The launcher still polls `day-status.json` + `RECORD.md` only and still re-wakes with a resume brief.

### 2. Scope sizing

- **cb-review:** One spawn = roughly **300k–350k tokens of agent context** for the worker. "One day's work" = a large, coherent chunk where multi-pack / multi-slice progress is OK; contiguous ownership preferred (same wave, disjoint file packs, or residual ship). Tiny one-file chores are explicitly discouraged unless the residual itself is tiny. Scope is sized by the launcher from `RECORD.md` residual + open PRs and written into the spawn prompt (optionally also `$RUN_ROOT/audits/day-scope-{N}.md` with goal, pack IDs, branch, PR links, stop conditions).
- **Reuse verbatim** (token budget, "prefer contiguous ownership", "don't under-scope into tiny chores").
- **Adaptation for brainstorming loop:** The unit of contiguous ownership changes from "disjoint file packs" to "one full cycle (D1→C1→D2→C2→vote) OR a partial cycle's residual". The day-scope doc becomes `$RUN_ROOT/cycles/day-scope-{N}.md` with goal, persona×seed matrix, shortlist target, kill/refine/advance stop conditions. The 300k–350k budget is preserved.

### 3. No human in the loop rule

- **cb-review:** Exact wording (§0.5.3): *"No human in the loop. Do not pause for 'should I continue?' — continue, ship, or leave a precise `Stopped at` + `day-status.json` if truly blocked (permissions, missing secrets, merge conflict needing human)."* And in §10.2 4c: *"It is the agent's job to wait properly — do not abandon the PR half-reviewed and do not ask a human to 'check later' unless truly blocked on secrets/access."* The only enumerated exceptions are: (a) permissions, (b) missing secrets, (c) merge conflict needing a human. When blocked: set `state=blocked`, write `blocked_reason`, write exact `Stopped at` + next action in `RECORD.md`, exit cleanly so the launcher can re-wake.
- **Reuse verbatim.** This is invariant rule #1 of autonomy (see below). The wording should be copied essentially unchanged.
- **Adaptation for brainstorming loop:** The "merge conflict needing human" exception has no analog (no code edits → no merge conflicts). Replace it with: "truly blocked = tool/retrieval failure after documented retries, or budget exhausted mid-verdict". Keep "permissions, missing secrets" verbatim. The "agent's job to wait properly" rule maps to: "agent's job to converge properly — do not abandon a cycle half-judged and do not ask a human to 'review the shortlist later'".

### 4. day-status.json

- **cb-review:** Lives at `$RUN_ROOT/audits/day-status.json`, launcher-readable. Fields: `state` ∈ `{running, shipping, waiting_coderabbit, blocked, complete}`, `scope_id`, `last_step` (short machine-readable), `branch`, `prs: {develop, main}`, `blocked_reason`, `updated_at` (ISO-8601), optional `notes`. Purpose: thin launcher poll file — the launcher checks this plus `RECORD.md` "Stopped at" only, **never** the worker's full session JSONL. It is what makes the launcher/worker split real: without it, the launcher would have to ingest the worker's transcript to know what's happening.
- **Reuse verbatim** (fields, states, purpose, location convention).
- **Adaptation for brainstorming loop:** Add fields: `cycle_id` (e.g. `cycle-3`), `phase` ∈ `{diverge_1, converge_1, diverge_2, converge_2, judging, research, synthesis, complete}` (replaces `waiting_coderabbit` etc.), `shortlist_size`, `verdicts_pending`. Drop `branch` and `prs` (no code ship). Add `next_cycle_constraints_extracted: bool`. The `state` set becomes `{running, waiting_judge, blocked, complete}`.

### 5. RECORD.md

- **cb-review:** Template (§8.1) sections: `## Status` table (State / Branch / Last updated / Continues from / RUN_ROOT), `## Goal this run`, `## Waves` table (Wave / Status / Notes), `## Done (chronological)`, `## In flight`, `## Stopped at` (exact next action if resuming), `## Residual / backlog` (priority table), `## Valuable notes` (env secrets, deploy gotchas, product assumptions, CI quirks), `## PRs / commits` (index), `## How to resume`. Updated at: run start, end of each wave, after each ship, run pause/stop. Rule: *"Never invent status — update RECORD (and day-status) after every material step."* Used by a cold launcher: open latest `agents/cd-review/*/RECORD.md`, read `Stopped at` + `Residual` + `day-status.json`, decide scope, re-wake worker.
- **Reuse verbatim** (sections, update cadence, "never invent status" rule, "How to resume" section).
- **Adaptation for brainstorming loop:** Rename `## Waves` → `## Cycles`, with rows per cycle (D1 / C1 / D2 / C2 / Vote / Research / Synthesis). Replace `## PRs / commits` with `## Shortlist / verdicts` (idea-id → kill/refine/advance → next-cycle constraint). `## Valuable notes` shifts from env secrets/CI quirks to "persona failure modes observed this run", "seed-diversity gaps", "novelty-archive additions". `## Stopped at` and `## Residual / backlog` keep the same role.

### 6. Resume protocol (§8.2)

- **cb-review:** Five steps. (1) Open latest `agents/cd-review/*/RECORD.md` (or user-specified date). (2) Read `Stopped at`, `Residual`, and `$RUN_ROOT/audits/day-status.json` if present. (3) **Launcher:** re-wake a day-scope agent with the residual scope (§0.5). **Day-scope:** continue mid-wave / mid-ship without waiting for a human. (4) Continue that run **or** create a new dated folder (§1) and link "continues from". (5) Never invent status — update `RECORD` (and `day-status`) after every material step.
- **Reuse verbatim.** This is invariant rule #3 of autonomy (the resume contract).
- **Adaptation for brainstorming loop:** The "mid-wave / mid-ship" phrase becomes "mid-phase / mid-verdict". Step 4 "continues from" linking is preserved exactly — a new dated folder can carry forward an unfinished cycle's shortlist. Everything else verbatim.

### 7. Wave separation (strict role separation)

- **cb-review:** §3: *"Reviewers do not spawn brainstormers. Brainstormers do not edit product code. Fixers do not re-open design when a brainstorm package already chose an approach."* Wave A (Audit): reads code + AGENTS.md, writes `audits/slices/S*.md`, NO children, NO product edits. Wave B (Brainstorm): reads slice findings + code locations, writes `brainstorms/{ID}.md`, NO children (research tools OK), NO product edits. Wave C (Fix): reads master packs + brainstorm packages, writes product code + `audits/fixes/P*.md`, NO children (unless orchestrator re-dispatches). L0 (day-scope orchestrator) is the **only** layer that decides sequencing, consolidates, ships, and re-dispatches waves. The flow is one-directional: A → B → C; no wave re-opens the prior wave's output.
- **Reuse the principle verbatim; adapt the wave names.**
- **Adaptation for brainstorming loop:** Wave names change from `audit → brainstorm → fix → verify` to `diverge (D1) → converge (C1) → diverge (D2) → converge (C2) → judge (vote) → research (verify/refine) → synthesize (constraint extraction)`. The no-re-litigation rules become: (a) research subagents do not re-open the diverge phase (they only kill/refine/advance ideas from the shortlist); (b) synthesis does not re-open research verdicts; (c) D2 subagents prepare BEFORE seeing D1's raw ideas (Stepladder — cf. 1-B #7) to prevent anchoring. L0 (day-scope orchestrator) remains the only sequencing/consolidation layer.

### 8. Disjoint file ownership

- **cb-review:** Orchestrator writes `audits/master.md` with **fix packs with disjoint file ownership**. Each Wave C fixer brief includes `OWNED FILES: {list only}` — a fixer may only touch files in its pack. This is what makes parallel Wave C safe: no two fixers can ever collide on the same file → no merge conflicts → no human merge intervention → autonomy preserved.
- **Reuse the principle verbatim; adapt the ownership unit.**
- **Adaptation for brainstorming loop:** Ownership unit changes from "files" to "idea-ids + persona+seed pair". Diverge subagents are dispatched with a **disjoint persona×seed matrix** (cf. 1-A, 1-C: no two subagents share persona+seed — kills LLM mode collapse per Deng & Brucks 2026). Each writes to `diverge/{persona}-{seed}.md` only. Research subagents are dispatched with a **disjoint shortlist slice** (each idea-id owned by exactly one research worker). The orchestrator's `master.md` analog is `converge/shortlist.md` + `research/verdicts.md` with the disjoint ownership table.

### 9. Ship protocol (§10.2)

- **cb-review:** Six-step flow runs autonomously inside the day-scope agent after each wave or scoped part. (1) SEED/OPS (CLI only, no MCP `functionSpec` dumps). (2) LAND ON DEVELOP: push product branch, open/reuse PR to `develop`, CI green, merge bottom-up if stacked. (3) OPEN PR INTO MAIN: `develop → main`, update `day-status` `state=shipping, prs.main=<n>`. (4) CODERABBIT WAIT + ITERATION: 4a sleep ~5min, fetch all reviews/comments/issue comments; 4b detect "review still pending" → sleep ~10min, recheck, repeat until CR finished; 4c rate-limits/flaky bot → wait 10–30+ min, retry, `@coderabbitai review` if needed, record attempts in `RECORD`; 4d confirm review is REAL before "nothing to fix" — empty CR is suspicious (wrong PR, wrong base, skipped, not-finished) — only accept empty after a completed pass with evidence; 4e fix → push → sleep ~5min → re-enter 4a. (5) MERGE INTO MAIN when CI green + CR residual empty/accepted. (6) CONTINUE NEXT PART OF SCOPE under same RUN_ROOT; ship again via this section; on scope closed set `state=complete`; if stop early set `blocked`/`stopped_at` precisely.
- **Drop most of it; adapt the meta-pattern.** The brainstorming loop has no `develop → main` PR and no CodeRabbit. The meta-pattern that survives: "the agent's job to wait properly — do not abandon the work half-finished and do not ask a human to check later."
- **Adaptation for brainstorming loop:** Replace the CodeRabbit wait loop with a **Judge verdict loop**: after research subagents write verdicts, the non-parallel Judge (orchestrator role, cf. 1-C) must produce kill/refine/advance for every shortlist idea before synthesis. The analog of "empty CR is suspicious" is "all-advance verdict is suspicious" (likely the research workers were sycophantic — re-dispatch one Devil's Advocate research worker). The analog of the 5m/10m waits is **no analog** — there is no external bot; the Judge verdict is synchronous and in-process. The "ship" target becomes `synthesis/{cycle-id}.md` (next-cycle constraints + shortlist with verdicts) written to the dated folder.

### 10. Dated run folders

- **cb-review:** Structure (§0): `agents/cd-review/YYYY-MM-DD/` per calendar day or explicit user start. Subdirs: `RECORD.md` (run narrative), `audits/slices.md` (slice map), `audits/slices/S*.md` (Wave A findings), `audits/master.md` (consolidated audit + fix packs), `audits/fixes/P*.md` (Wave C fix reports), `audits/verify.md` (check/test results), `audits/day-status.json` (thin launcher poll), `brainstorms/{ID}.md` (Wave B decision packages). Rule (§1.4): *"Do not delete previous date folders. Prior days are history. Only create a new dated folder. Optionally note 'continues from 2026-07-18' in the new RECORD."* `RUN_ROOT=agents/cd-review/YYYY-MM-DD` is the only path agents write to. Never write review artifacts under `audits/` at repo root or `loops/`.
- **Reuse verbatim** (folder shape, "do not delete prior days", "continues from" linking, `RUN_ROOT` discipline, "nothing canonical at repo root").
- **Adaptation for brainstorming loop:** Subdirs become `diverge/`, `converge/`, `research/`, `synthesis/`, plus shared `RECORD.md` + `cycles/day-status.json` + `cycles/slices.md` analog (which is `cycles/persona-seed-matrix.md`). The naming `brainstorms/` is dropped (the whole loop is brainstorming). The "do not nest brainstorms under audits" rule (§0) becomes "do not nest diverge artifacts under research/".

### 11. Single source of truth principle

- **cb-review:** Preamble: *"This file is the single source of truth for the loop. Dated run artifacts live under: `agents/cd-review/YYYY-MM-DD/`."* §1.5: *"Never write review artifacts under `audits/` at repo root or `loops/`."* §12 history table documents relocations (2026-07-17 original under `loops/cb-review.md` + root `audits/`; 2026-07-18 relocated to `agents/cd-review/`). `LOOP.md` is always-current protocol; dated folders are immutable history.
- **Reuse verbatim.** This is invariant rule #7 of autonomy.
- **Adaptation for brainstorming loop:** New loop lives at `agents/brainstorm/LOOP.md` (per the worklog preamble). Dated runs under `agents/brainstorm/YYYY-MM-DD/`. Nothing canonical at repo root or under `loops/`. Same history-table convention at the end of LOOP.md.

### 12. North-star ordered criteria

- **cb-review:** Preamble + §2: numbered, ordered list. (1) Readability, (2) Clarity of intent and module boundaries, (3) Brevity (delete dead code; collapse duplication), (4) Consistency with AGENTS.md / advanced Exigo patterns, (5) Correctness / security when it does not worsen 1–4. Mantra: *"readable → clear → short → consistent → correct"*. Tie-breaker: *"Bugs that exist because of muddled structure rank higher than clever micro-bugs in otherwise clean code."* Non-goals list is also explicit: no new features, no drive-by refactors outside owned files, no taste-rewrites, no test-matrix expansion without a failure mode, no review agents spawning brainstorm children.
- **Reuse the structural pattern verbatim** (ordered numbered list + mantra + tie-breaker sentence + explicit non-goals list).
- **Adaptation for brainstorming loop:** New north-star for ideation: (1) Novelty (does this idea differ from prior-cycle ideas AND from peer subagents' ideas in this cycle?), (2) Feasibility (is the load-bearing assumption falsifiable at low cost?), (3) Relevance (does it address the cycle's problem statement, not a neighboring one?), (4) Diversity contribution (does it occupy an unexplored region of the idea space, per the novelty archive?), (5) Honesty (are the failure modes and assumptions stated, not hidden). Mantra: *"novel → feasible → relevant → diverse → honest"*. Tie-breaker: *"Ideas that exist because of mode collapse on a popular framing rank lower than weird ideas with a falsifiable assumption."* Non-goals: no re-litigation of prior-cycle verdicts, no research subagent editing diverge artifacts, no Judge spawning diverge subagents, no idea accepted without a pre-mortem (cf. 1-B #6), no shortlist element without a kill/refine/advance verdict.

### 13. Subagent rules

- **cb-review:** Wave A/B/C workers are subagents of the day-scope agent. They do NOT replace it. Rules: Wave A — NO children, NO product edits, write only `audits/slices/{SLICE_ID}.md`. Wave B — NO children (research tools OK), NO product edits, write only `brainstorms/{BRAIN_ID}.md`. Wave C — NO children (unless orchestrator re-dispatches), write product code + `audits/fixes/{PACK_ID}.md`, only owned files. "Review agents spawning brainstorm (or any) child agents" is explicitly listed under Non-goals (§2). Optional nested CLI agents when the harness benefits (isolation), but *"Never require the human to re-enter."* The subagent briefs (§5.2, §6.2, §7.2) are templated and self-contained: role, `RUN_ROOT`, `SLICE`/`BRAIN_ID`/`PACK`, paths/findings/owned-files, rules, output format, return-to-orchestrator contract.
- **Reuse the structural rules verbatim** (no children unless orchestrator re-dispatches, write-only-your-artifact, never require human re-entry, templated self-contained briefs).
- **Adaptation for brainstorming loop:** Wave A/B/C briefs become D1/D2/Judge/Research/Synthesis briefs. D1/D2 briefs add an explicit `PERSONA={dreamer|skeptic|engineer|outsider|synthesizer}` and `SEED={seed-id}` field (cf. 1-A persona set, 1-C diversification matrix). Judge brief is non-parallel (single orchestrator role, cf. 1-C). Research briefs add `ASSUMPTION_TO_FALSIFY={id}` and `REACT_BUDGET={tokens}` (cf. 1-A ReAct, 1-B assumption testing). The "no children" rule has one **new** exception: a research subagent MAY spawn a single `tool_call` (web_search, repo read) but never a nested reasoning agent — this preserves cb-review's "no nested brainstorm spawn" rule (no infinite recursion, cf. 1-C recursive-MAS failure modes).

### 14. Stop conditions

- **cb-review:** Day-scope agent stops when: (a) scope is complete → set `day-status.state=complete`, stop cleanly, update `RECORD.md` final state; (b) truly blocked (permissions / missing secrets / merge conflict needing human) → set `state=blocked`, `blocked_reason`, write exact `Stopped at` + next action in `RECORD`, exit so launcher can re-wake; (c) user cancels the loop. When stopping early: leave precise `Stopped at` + `day-status.json` so launcher can resume. §10.2 step 6: *"If day scope is closed: set day-status state=complete and stop cleanly. If you must stop early: set blocked/stopped_at precisely so the launcher can wake you."* §0.5.3: *"always keep `RECORD.md` current so a cold launcher can re-wake you correctly."*
- **Reuse verbatim** (state=complete / state=blocked + blocked_reason + Stopped at + next action + exit so launcher can re-wake).
- **Adaptation for brainstorming loop:** A cycle is "complete" when **all three** hold: (a) shortlist is converged (vote produced), (b) every surviving idea has a kill/refine/advance verdict from research, (c) next-cycle constraints are extracted and written to `synthesis/{cycle-id}.md`. Stopping early (budget exhausted mid-verdict) leaves: `day-status.state=blocked`, `blocked_reason="budget_exhausted_mid_verdict"`, `RECORD.Stopped at = "research verdict pending for idea {id}; re-dispatch one research worker with same assumption and react budget X"`. The launcher re-wakes with that exact residual.

## The 5-7 invariant rules that grant autonomy

These are the load-bearing rules. Remove any one and the loop stops being autonomous.

1. **No human in the loop inside the day-scope agent.** It never pauses for "should I continue?". It continues, ships, or writes a precise `Stopped at` + `blocked_reason` and exits. The only enumerated exceptions are permissions, missing secrets, and (cb-review only) merge conflicts needing a human. (§0.5.3)
2. **Launcher and day-scope agent are separate processes; the launcher never ingests the worker's transcript.** The launcher polls only `day-status.json` + `RECORD.md` "Stopped at". This keeps the launcher's context thin enough to re-wake many times, and keeps the worker autonomous (no parent watching its scratchpad). (§0.5.1, §0.5.2 step 4)
3. **`day-status.json` + `RECORD.md` "Stopped at" are the ONLY resume contract.** Without these two artifacts a cold launcher cannot re-wake the worker — it would have to re-brief from scratch, which requires a human. The rule "never invent status — update RECORD (and day-status) after every material step" is what makes the contract trustworthy. (§0.5.4, §8.2 step 5)
4. **Strict one-directional wave separation + disjoint ownership.** Wave A cannot spawn Wave B; Wave B cannot edit product code; Wave C cannot re-open design. Parallel workers (Wave C fixers) own disjoint file sets. Without this: (a) re-litigation loops where waves re-open each other forever, (b) parallel-worker merge conflicts that force a human merge. (§3, §7.1)
5. **The agent's job to wait properly / converge properly.** cb-review: do not abandon a PR half-reviewed, do not ask a human to "check later", the 5m/10m/10-30m CodeRabbit wait loops are mandatory. Brainstorming-loop analog: do not abandon a cycle half-judged, do not ask a human to "review the shortlist later", the Judge verdict loop is mandatory. Without this, the loop either ships incomplete work or breaks the HITL rule by punting to a human. (§10.2 4c, §10.2 4d)
6. **Scope-sized spawns (~300k–350k tokens) with contiguous ownership.** One spawn = one coherent day-scope, not a tiny one-file chore. Without this, the launcher re-spawns constantly (each spawn needs a human-triggered launcher session) and the loop loses its "runs for a day without me" property. (§0.5.2 step 2, §0.5.3)
7. **Single source of truth: `LOOP.md` is canonical protocol; dated `YYYY-MM-DD/` folders are immutable run history; nothing canonical at repo root.** Without this, two agents reading "the loop" read different versions; a cold launcher cannot tell which protocol a stopped run was following; runs cannot be safely continued across protocol revisions. (Preamble, §0, §1.4, §1.5)

## What must change for a brainstorming loop

The cb-review autonomy pattern is **directly transferable** — the launcher/day-scope split, the `day-status.json` + `RECORD.md` resume contract, the dated folder discipline, the no-HITL rule, the single-source-of-truth principle, the strict wave separation, and the stop-condition shape all carry over essentially verbatim. The brainstorming loop should reuse these as-is: they are not domain-specific to code review, they are domain-specific to **long-running autonomous agent work that must survive context exhaustion and process restarts**, which is exactly what a multi-cycle brainstorm↔research loop is.

The substantive changes are all in **what the waves produce and how they connect**. cb-review's product is code edits shipped via PRs; the brainstorming loop's product is idea shortlists + research verdicts + next-cycle constraints, all written to dated folders (no `develop → main`, no CodeRabbit). Wave names change from `audit → brainstorm → fix → verify` to `diverge (D1) → converge (C1) → diverge (D2) → converge (C2) → judge → research → synthesize`, with the no-re-litigation rule preserved (research cannot re-open diverge; synthesis cannot re-open research verdicts) and the disjoint-ownership unit shifting from files to idea-ids + persona×seed pairs (cf. 1-A's 5-persona set, 1-C's diversification matrix). The "agent's job to wait properly" rule maps onto "agent's job to converge properly" — the analog of CodeRabbit's external wait loop is the internal Judge verdict loop, and the analog of "empty CR is suspicious" is "all-advance verdict is suspicious" (sycophancy signal → re-dispatch one Devil's Advocate research worker).

The third axis of change is **diversity pressure**, which cb-review does not need (its reviewers are inherently diverse because they own disjoint slices of the codebase) but the brainstorming loop must enforce structurally. cb-review's Wave A "one agent per slice" gives natural diversity for free; the brainstorming loop's diverge subagents would collapse to mode without explicit persona×seed diversification (Deng & Brucks 2026, cf. 1-A) and Stepladder-style D2 isolation from D1's raw ideas (cf. 1-B #7). This is the only place where the brainstorming loop is **strictly more constrained** than cb-review: cb-review's autonomy works with homogeneous workers because the work is partitioned by file ownership; the brainstorming loop's autonomy only works if workers are heterogeneous by design, because the work is partitioned by idea-space region and idea-space is shared.
