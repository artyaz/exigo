# Decision Package — DP-002

**TRIGGER:** ~600+ lines of dead code across 15+ files inflate bundle size, confuse contributors, and ship test-only mutations to production Convex.

**NORTH_STAR_HURT:** Maintainability (cognitive load, onboarding friction), Performance (unused TRPCReactProvider wraps every page), Security surface (testUtils internal mutations deployed to prod).

**LOCATION:** `src/trpc/`, `src/server/api/`, `src/server/db.ts`, `prisma/`, `generated/`, `src/app/api/trpc/[trpc]/route.ts`, `src/app/_components/post.tsx`, `src/app/PaddleCheckoutReceiver.tsx`, `src/app/layout.tsx`, `convex/auth.ts`, `convex/authDecorators.ts`, `convex/deepDives.ts`, `convex/testUtils.ts`, `convex/courseTutor.ts`, `convex/schema.ts`, `src/lib/sse.ts`, `shared/courseTopicRequests.ts`

Legacy schema fields (`clerkPlanSlug`, `periodEnd`) on the subscriptions table have zero runtime readers. The root layout still advertises "Generated by create-t3-app" in its meta description.

**QUESTION:** How do we safely remove all verified dead code in a single ordered pass, minimizing risk to production while eliminating ~600 lines of waste?

---

## Recommendation

- **Approach name:** Surgical Multi-Phase Deletion (safest-first ordering)
- **One-paragraph rationale:** Every finding has been grep-verified as having zero production consumers. Deleting dead code is the highest-leverage maintenance action: it reduces bundle size, eliminates a confusing dual-stack (tRPC + Convex), removes test-only mutations from production, and cuts onboarding time. Ordering by confidence (pure dead files first, then dead exports within live files, then data-dependent shims last) ensures each step is independently deployable and revertable. The legacy chat shim is flagged for data verification before removal since it touches user-visible behavior.
- **Why not alternatives:** "Leave it" accumulates confusion and bundle cost. "Rewrite/refactor" violates delete > move > rewrite convention. "Move to a dead-code branch" adds git overhead with no benefit — git history preserves everything.

### Research notes
- The tRPC stack is a create-t3-app scaffold artifact. The app migrated to Convex + Next.js API routes but never cleaned up.
- `testUtils.ts` uses `internalMutation`/`internalQuery`, meaning it's deployed to Convex production but only callable via `internal.*` (server-side). The only caller is `test-backend-limits.mjs`, a manual integration script. Removing it breaks that script but has zero production impact.
- The legacy chat shim (I-001-005) was likely added during a spaceId migration. If all chats now have `spaceId` set, the shim is pure overhead (N+1 queries per space load).
- `convex/schema.ts` comment at L93-94 explicitly documents `clerkPlanSlug`/`periodEnd` as legacy — the original author intended removal.
- Removing `clerkPlanSlug`/`periodEnd` from schema is safe because they're `v.optional()` — existing documents retain the fields, Convex just stops validating them on write.
