## Findings

### F-S9-001 — P0 — Security / authz boundary

**Category:** security  
**Location:**  
- `src/app/actions/aiSettings.ts` (passes `userId` into `userSettings:getMine` / `save`)  
- `src/server/ai/resolve.ts` (`userSettings:getCipher` with `userId`)  
- Evidence dependency: `convex/userSettings.ts` (no identity check — S3)

**Evidence:**  
Server actions correctly take Clerk `userId`, but Convex handlers accept **any** `userId` string with no `getAuthedContext` / subject match. `getCipher` returns ciphertext for the requested user; `save` upserts arbitrary users’ settings. Encryption keeps plaintext off Convex, but IDOR still allows overwriting another user’s provider/baseUrl/key material and reading their opaque cipher.

```13:29:convex/userSettings.ts
export const getMine = query({
  args: { userId: v.string() },
  handler: async (ctx, { userId }) => {
    const row = await ctx.db
      .query("userSettings")
      .withIndex("by_user", (q) => q.eq("userId", userId))
      .unique();
    // ...
```

**North-star harm:** Correctness + security; trust model is unreadable (“who enforces ownership?”).  
**Minimal fix:** Per **S9-B006** approach A/B: authorize in Convex from identity; treat action-supplied `userId` as non-authoritative.  
**Effort:** M (mostly S3; S9 follow-up to drop/assert userId).  
**Test plan:** Authed user A cannot `getMine`/`save`/`getCipher` for user B; happy path still works for self.  
**Brainstorm:** `audits/brainstorm/S9-B006.md`

### F-S9-004 — P1 — Silent empty API key + silent custom-provider fallbacks

**Category:** correctness / security observability  
**Location:** `src/server/ai/resolve.ts` L30–72  

**Evidence:**

```30:36:src/server/ai/resolve.ts
export function defaultGeminiProvider(model?: string): AiProvider {
  return new GeminiProvider({
    kind: "gemini",
    model: model ?? DEFAULT_GEMINI_MODEL,
    apiKey: process.env.GOOGLE_GEMINI_API_KEY ?? "",
    label: "google",
  });
}
```

Settings query failures, missing OpenAI key material, and decrypt failures all **silently** return default Gemini — no log. Sibling routes throw when the env key is missing. Users with broken custom keys appear to “use Gemini” without knowing.

**North-star harm:** Correctness + clarity of failure modes.  
**Minimal fix:** Per **S9-B003** approach A: throw if default key missing; warn on fallback reasons (never log secrets).  
**Effort:** S  
**Test plan:** Unit: missing `GOOGLE_GEMINI_API_KEY` throws; decrypt failure path logs/falls back.  
**Brainstorm:** `audits/brainstorm/S9-B003.md`

## Patterns

1. **Dual AI stacks** — playground multi-provider (`src/server/ai`) vs product Gemini (routes + Convex). Comments claim one stack.
2. **Auth at Next edge, authz assumed in Convex** — actions always `auth()` + `createAuthedConvexClient`, but not all Convex functions enforce identity (settings IDOR).
3. **ActionResult schism** — learn/spaces evolved structured results; knowledge/aiSettings remain throw-based.
4. **Solid crypto boundary** — encrypt on Next, store cipher on Convex (`secrets.ts`) is the right split; failure modes are the debt.
5. **Legacy T3 spine** — tRPC/Prisma Post next to real server modules dilutes “what is src/server for?”
6. **Payments factory is thin and good** — singleton `getPaymentProvider()`; domain side effects correctly outside (if documented).
