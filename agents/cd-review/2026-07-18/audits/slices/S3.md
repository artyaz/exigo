## Findings

### F-S3-001 — `questions.ts` public API has no real auth (answer leak + IDOR)

| Field | Value |
|-------|--------|
| **Severity** | **P0** |
| **Category** | security / auth |
| **Location** | `convex/questions.ts` L4–L124 |
| **Evidence** | `getForTest`, `get`, `getForSpace`, `getIncorrectForTopic` never call `ctx.auth` — any client with the deployment URL can read questions **including `answer` (perfect outline)**, `userAnswer`, `aiFeedback`. Mutations `create` / `updateFeedback` authorize only via **client-supplied** `args.userId` vs `space.userId`, never `identity.subject`. Callers include client `useQuery(api.questions.getForTest)` and API routes that pass `userId` as a plain arg. |
| **North-star harm** | **Correctness** (security) first; clarity second (auth pattern diverges from every other module). |
| **Minimal fix** | Derive user from `getAuthenticatedUserId` / `getAuthedContext`; authorize via question→test→space; **remove `userId` from mutation args**; gate all queries. Update generate/validate routes to drop `userId`. |
| **Effort** | M |
| **Test plan** | Unit/handler tests: unauthenticated getForTest returns deny; attacker userId cannot updateFeedback; owner can. |
| **Brainstorm** | `audits/brainstorm/S3-B001.md` |

### F-S3-002 — `userSettings` trust client `userId` with zero identity check

| Field | Value |
|-------|--------|
| **Severity** | **P0** |
| **Category** | security / auth |
| **Location** | `convex/userSettings.ts` L13–L100 |
| **Evidence** | `getMine`, `getCipher`, `save` never call `ctx.auth`. Any caller can pass an arbitrary Clerk `userId` to read provider metadata / ciphertext or **overwrite** another user’s `provider`, `baseUrl`, and key material. Comment L4–8 claims Next.js is the security boundary — false for public Convex functions. Next server actions *do* auth, but the Convex functions remain publicly invocable. Overwrite of `baseUrl` + stored key can redirect a victim’s AI traffic after they set a custom key. |
| **North-star harm** | Correctness (authz); clarity (liar comment). |
| **Minimal fix** | `getAuthenticatedUserId` at top of each handler; drop `userId` from args; query/patch by identity only. Update `aiSettings.ts` / `resolve.ts` call sites. |
| **Effort** | S–M |
| **Test plan** | Handler tests: no identity → ConvexError; identity A cannot read/write B’s row. |
| **Brainstorm** | `audits/brainstorm/S3-B002.md` |

## Patterns

1. **Auth is uneven by file age.** `exerciseComments` is the gold pattern; `questions` / `userSettings` are ungated; middle-aged modules half-use `getAuthedContext` and half-trust `args.userId`.
2. **Magic `default_user`** is a second, weaker ACL sprinkled inconsistently.
3. **Node-runtime AI split** was started (`*Actions.ts`) but not finished — dual actions + model/prompt drift.
4. **Limit enforcement was reimplemented** (calendar month) instead of using `usageService` (rolling 30-day).
5. **Tests that reimplement handlers** create green CI without protecting production (delete-test wins hard on `tests.test.ts`).
6. **Error types:** mix of `throw new Error(...)` vs `ConvexError` from decorators — clients cannot rely on structured codes.

## Recommended fix order

1. **F-S3-001, F-S3-002** (P0 auth) — ship first; coordinate Next call sites.  
2. **F-S3-005** (default_user) — same PR family as auth helpers.  
3. **F-S3-003** (+ F-S3-008 chat/send cleanup) — single AI action home.  
4. **F-S3-004** — limits via usageService (with S1 usage auth if needed).  
5. **F-S3-006, F-S3-009, F-S3-010** — API shape cleanup.  
6. **F-S3-007** — delete liar tests (can land anytime; pure risk reduction).

## Explicit non-issues

- `testUtils.ts` internal-only test fixtures — appropriate for Convex testing; not a public auth surface.  
- `exerciseComments.ts` auth model — already correct; use as template.  
- Pure helpers `sortTestsByCreationDesc` / `countAnsweredQuestions` / `enrichTestForList` — clear and tested honestly.  
- Ciphertext-only key storage design (encrypt in Next) — sound; the bug is missing Convex identity checks, not the crypto boundary.  
- Prisma dual-DB — not present in this slice.
