## Findings

### F-S2-001 · P0 · security  
**Title:** Public message mutations allow forging `teacher` / `system` / `tutor` roles  

**Location:**  
- `convex/courseLessonMessages.ts` `send` (lines 5–38)  
- `convex/courseTutor.ts` `sendMessage` (lines 168–188)  

**Evidence:**  
```ts
// courseLessonMessages.send — client supplies role
role: v.union(v.literal("teacher"), v.literal("user"), v.literal("system")),
// …insert with args.role after ownership check only
```  
Any authenticated course owner can insert teacher/system content into lesson history consumed by teach / summarize / clarifier prompts. Same pattern for tutor chats (`role: "tutor" | "system"`). API routes also write via this public API (`api.courseLessonMessages.send` with role teacher).

**North-star harm:** Correctness (conversation integrity, prompt poisoning); clarity (role looks like a privilege but is free text).  

**Minimal fix:** Public send hardcodes `role: "user"`; only `sendInternal` / `sendMessageInternal` write non-user roles. Coordinate S8 route migration if routes currently pass teacher role on public mutation (prefer routes → internal via action).  

**Effort:** M  
**Test plan:** Unit/integration: public send rejects or ignores teacher role; internal still inserts teacher.  
**Brainstorm:** [`audits/brainstorm/S2-B002.md`](../brainstorm/S2-B002.md)

### F-S2-002 · P0 · security  
**Title:** `normalizeTopic` creates a course in any `spaceId` without space ownership check  

**Location:** `convex/courseAi.ts` `normalizeTopic` (~89–146) → `internal.courses.createInternal`  

**Evidence:** Auth is educator-only; `spaceId` is never loaded. `createInternal` inserts `{ spaceId, userId: auth.userId, ... }`. Attacker educator can plant courses into a victim’s space (victim `getForSpace` lists all courses for that space after space ownership check — pollution visible to victim).  

Contrast: `courses.create` / `createCourseFromNormalized` correctly check `space.userId === auth.userId`.  

**North-star harm:** Correctness (IDOR-style data pollution); consistency (sibling create path is correct).  

**Minimal fix:** Before `createInternal`, load space and require `space.userId === auth.userId` (same as mutations).  

**Effort:** S  
**Test plan:** Action with foreign spaceId throws Unauthorized.  
**Brainstorm:** [`audits/brainstorm/S2-B001.md`](../brainstorm/S2-B001.md)

### F-S2-003 · P1 · security  
**Title:** Baseline AI actions ignore `courseId` for authorization  

**Location:** `convex/courseAi.ts` `generateBaselineQuestion` (~196–262), `evaluateBaselineAnswer` (~265–308)  

**Evidence:** Both call `requireEducatorAccess` then run Gemini. They never `getInternal(courseId)` or check `course.userId`. `courseId` is dead for authz; `courseTopic` is fully client-supplied. Any educator burns shared Gemini quota; ownership of the course is unenforced.  

**North-star harm:** Correctness / consistency with `generateModule` / `setMasteryGoals` which do load course + owner check.  

**Minimal fix:** Load course; require owner; prefer server `refinedTitle` as topic source.  

**Effort:** S  
**Test plan:** Non-owner educator gets Unauthorized.  
**Brainstorm:** [`audits/brainstorm/S2-B001.md`](../brainstorm/S2-B001.md)

### F-S2-004 · P1 · security / structure  
**Title:** Public `courses.updatePhase` lets clients set any phase (state-machine bypass); also skips educator gate  

**Location:** `convex/courses.ts` `updatePhase` (67–80)  

**Evidence:** Authenticated owner may patch `phase` to any `COURSE_PHASE` literal including `"completed"` / `"lesson"` without orchestrator. Grep shows **no frontend callers** — dead public surface that still exists on the network. Sibling `updatePhaseInternal` / `updateProgress` are the real writers.  

**North-star harm:** Correctness if abused; brevity (dead export); clarity (two phase writers).  

**Minimal fix:** Delete public `updatePhase` (keep internal). All phase changes via orchestrator / internal progress.  

**Effort:** S  
**Test plan:** Confirm no imports; deploy after delete.

### F-S2-005 · P1 · bug / hot-path  
**Title:** Course state machine never transitions to `completed` (infinite module loop)  

**Location:** `convex/courseOrchestrator.ts` `module_complete` (137–162), `completed` (164–166)  

**Evidence:**  
- `module_complete` always sets phase → `module_generation` and calls `generateModule` again.  
- Repo-wide: no backend write of `phase: "completed"` (only schema + UI).  
- UI (`learn/[courseId]/page.tsx`) renders “Course Completed!” when `phase === "completed"` — **liar contract**.  

**Pre-mortem:** Users never finish; modules accumulate forever; cost unbounded.  

**North-star harm:** Correctness; clarity of phase machine vs AGENTS.md diagram.  

**Minimal fix:** Explicit terminal policy (recommended: max modules constant, or user `completeCourse`); on threshold set `phase: "completed"`. Document transition table at top of orchestrator.  

**Effort:** M  
**Test plan:** After N modules, advance yields completed and no further generateModule.  
**Brainstorm:** [`audits/brainstorm/S2-B003.md`](../brainstorm/S2-B003.md)

### F-S2-006 · P1 · bug / structure  
**Title:** `generateModule` is public, phase-unguarded, and races under concurrent `advanceCourse`  

**Location:**  
- `convex/courseAi.ts` `generateModule` (311–468)  
- `convex/courseOrchestrator.ts` calls `api.courseAi.generateModule` (public) in two arms  

**Evidence:**  
1. Client can call `generateModule` directly while phase is `lesson` / `baseline` — still inserts module at `existingModules.length` and force-patches phase to `lesson`.  
2. Actions are non-transactional: two concurrent advances both read length L, both insert moduleIndex L (or L and L after race), both set progress — duplicate/corrupt syllabus.  
3. `module_generation` and `module_complete` arms duplicate the same generate + first-lesson goals block (~40 lines twice).  

**North-star harm:** Correctness (hot path); readability (duplication).  

**Minimal fix:** Internalize generateModule (or require phase ∈ {module_generation}); orchestrator uses `internal.*`; extract shared “start next module” helper; optional claim mutation before AI.  

**Effort:** M  
**Test plan:** Double-advance concurrent test / manual stress; direct client generateModule rejected off-phase.  
**Brainstorm:** [`audits/brainstorm/S2-B003.md`](../brainstorm/S2-B003.md)

## Patterns (cross-cutting)

1. **Three auth dialects** in one slice: full authed context + educator, bare userId, and “public read / trust client role”.  
2. **State machine is UI-documented but backend-incomplete** (`completed` never written; phase writable publicly; generateModule side-doors).  
3. **AI+DB orchestration sprawl** in `courseAi.ts` with a second SSE stack in Next — dual sources of truth for teach/clarify.  
4. **JSON blobs** for structured lesson data vs one typed island (`checkpointStates`).  
5. **Copy-paste orchestrator arms** (`module_generation` ≈ `module_complete`).  
6. **Internal vs public API confusion** (orchestrator → public action → re-auth; messages public for server writes).
