## Findings

### F-S4-001 — P1 · structure + bug  
**Title:** `validate.ts` is a god module; reaction expressions skip unknown-ref checks  

**Category:** structure / correctness  
**Location:** `runtime/validate.ts` (entire file; reactions ~309–370, `knownRefs: null` at 320 & 336)  
**Evidence:** Bindings, evaluator, and display layers call `checkExpr` with a closed `knownRefs` set. Reaction `when`/`to` pass `knownRefs: null`, so bare typos (`counnt + 1`, `ghost`) only surface as runtime `ExprError` during play. The same file also owns structured/legacy surface policy, every display-layer field walk, codeProbe harness compatibility, and obs schema merge (~733 lines).  
**North-star harm:** Authors/models cannot trust static validation on the hottest expressions (reactions); readers cannot hold the gate in one mental page.  
**Minimal fix:** Per **S4-B001** approach B — extract display/codeProbe validators; set reaction refs to `state|bindings|event` roots (not null); prefer `event.<field>` for payloads.  
**Effort:** M  
**Test plan:** `validateSpec` reaction with bare unknown ident fails; `event.value` / `n + 1` still pass; existing suite green.  
**Brainstorm:** [`audits/brainstorm/S4-B001.md`](../brainstorm/S4-B001.md)

### F-S4-003 — P1 · bug / liar contract  
**Title:** JS observation schema types do not match emitted values  

**Category:** correctness / consistency  
**Location:** `harness/jsObservationCore.ts` `JS_OBSERVATION_SCHEMA` ~73–98; `harness/types.ts` `ObsFieldType`; contradicted by `observation.test.ts` (`args: [5]`)  
**Evidence:** Schema declares `enter.args: "string"` but `enter` pushes `args: args.map(toValue)` (array). `exit`/`write`/`mark` declare `value: "number"` while `toValue` emits arbitrary JSON Values. Validator only checks field *names* on `event.*` for `obs:<kind>`, so the type half of the “typed API” is fiction.  
**North-star harm:** Authors, autocomplete docs, and future type-checks lie; repair loops learn the wrong shape.  
**Minimal fix:** Per **S4-B003** approach A — widen `ObsFieldType` with `array`/`value`; fix schema rows to match emit.  
**Effort:** S  
**Test plan:** Schema field presence tests still pass; optional assert `typeof`/Array for sample kinds.  
**Brainstorm:** [`audits/brainstorm/S4-B003.md`](../brainstorm/S4-B003.md)

### F-S4-007 — P2 · structure / perf  
**Title:** Playability search rebuilds full history per edge  

**Category:** structure / performance  
**Location:** `runtime/simulate.ts` ~107–182  
**Evidence:** BFS stores event sequences; each node `replay(spec, seq)` constructs a new `ReactiveVM` and re-dispatches the full history; each candidate action does it again. Visited key is `JSON.stringify(vm.state)`. Limits `MAX_NODES=5000`, `MAX_DEPTH=16` paper over the quadratic cost.  
**North-star harm:** Algorithm does not match the mental model; authoring latency grows opaque with control fan-out.  
**Minimal fix:** Per **S4-B007** approach B — VM `fork()` sharing compiled ASTs; one dispatch per edge.  
**Effort:** M  
**Test plan:** `simulate.test.ts` all cases; optional assert lower VM constructions.  
**Brainstorm:** [`audits/brainstorm/S4-B007.md`](../brainstorm/S4-B007.md)

### F-S4-009 — P2 · inconsistency  
**Title:** Markup parse vs `validateSpec` contract gap for structured required fields  

**Category:** consistency / clarity  
**Location:** `markup/parse.ts` `buildExercise` (optional prompt/think); `runtime/validate.ts` ~279–287 (structured requires non-empty `prompt` + `criticalThinking`)  
**Evidence:** `parseMarkup` succeeds without `<prompt>` / `<think>`; structured validation then hard-errors. Two gates with different bars force authors to discover rules only after the second stage.  
**North-star harm:** Dual error surfaces; markup is not a faithful frontend for the IR contract it claims to lower onto.  
**Minimal fix:** After successful tree validate, either (a) emit parse errors for missing prompt/think when a stage is present, or (b) document that validate is the hard gate and have parse attach soft warnings — prefer (a) for one author-facing bar. **L2 skipped: design space small; mirror validate rules in buildExercise.**  
**Effort:** S  
**Test plan:** Markup missing think with arena stage → parse error; full exemplar still parses.  
**Brainstorm:** skipped (trivial once policy chosen; prefer mirror validate)

## Patterns

1. **God modules on the authoring spine** — `validate.ts` and `parse.ts` grew every concern that “has to run before the VM.”
2. **Contracts that document ambition more than reality** — obs schema types, `allowSequentialWrite` name, blank/choice comments, ternary punct.
3. **Duplication at the JS sandbox seam** — two harnesses, one mechanism, drifting lists.
4. **Static gates unevenly strict** — display/bindings closed refs; reactions open; markup softer than validate.
5. **Generally strong tests** — expr/vm/validate/harness coverage is a strength; use it as a net for structural peels.
