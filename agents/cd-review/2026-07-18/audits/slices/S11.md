**Category:** correctness (ghost contract)  
**Location:** `src/app/tests/[testId]/page.tsx` (sessionStorage reads ~245, ~350, ~473, improvements gate ~400); writers: **none in repo**  
**Evidence:**  
- Client only: `sessionStorage.getItem(\`exigo_test_topic_${tId}\`)`

**Minimal fix:** Use `test.knowledgePieceId` as sole source; delete sessionStorage contract.  
**Effort:** S  
**Test plan:** Create test from a specific piece → open detail → confirm generate body / improvements path receive piece id without any sessionStorage seed.

### F-S11-006 — P2 / clarity (settings AI)  
**Category:** error handling / security-adjacent UX  
**Location:** `src/app/settings/page.tsx` L55–66, L72–90  
**Evidence:**  
```55:66:src/app/settings/page.tsx
  React.useEffect(() => {
    let alive = true;
    getAiSettings()
      .then((s: AiSettingsView) => {
        if (!alive || !s) return;
        ...
      })
      .catch(() => undefined)
      .finally(() => alive && setLoading(false));
```  
Load failures (Unauthorized, network) are swallowed; UI shows empty defaults as if settings loaded. Save path surfaces errors correctly.  
**North-star harm:** Clarity — user cannot tell “no custom key” from “failed to load encrypted settings.”  
**Minimal fix:** Surface load error in `msg`; do not leave form in a false “loaded clean” state. Optionally disable save until load succeeds.  
**Effort:** S  
**Test plan:** Force `getAiSettings` reject → error banner; success path unchanged.  
**Brainstorm:** L2 skipped: trivial (single catch path)

## Patterns

1. **Two UI dialects:** Tailwind product pages vs playground/settings CSS-string inject (exercise design system).  
2. **Tests UI forked three ways:** global list (`@ts-nocheck`), space `TestGrid` (typed + filters), detail god page.  
3. **Ghost contracts:** sessionStorage topic key never written; empty-state copy lies about filters.  
4. **Payment init not shared** between intentional inline checkout and Paddle return URL receiver.  
5. **Dead T3 residue** (`post.tsx`) still sitting next to real auth/legal components.  
6. **Auth pages are relatively clean** — shared `auth-ui` + `legal-ui` is the slice’s best consistency example.  
7. **Playground presets** are data-heavy but honest and tested; not a priority cut.
