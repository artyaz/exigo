## Decision Package — S10-B005

### Recommendation
- Approach name: **Keep `createAuthedConvexClient` as the public entry; extract pure helpers; drop Proxy if a thin wrapper method is enough**
- One-paragraph rationale: `convexClientAuth.ts` mixes token fetch, JWT payload peek, OTLP logging, PostHog exception capture, and a `Proxy` over `ConvexHttpClient`. The Proxy is clever but forces every reader to understand Reflect traps for three methods. Clarity wins come from (1) deleting duplicate PostHog init (B002), (2) optional thin wrappers `loggedQuery/loggedMutation/loggedAction` OR a single `withConvexLogging(client, meta)` that assigns wrapped methods without Proxy, and (3) leaving `getConvexUrlOrThrow` / `fetchConvexTemplateTokenOrThrow` as the exported building blocks. Full rewrite of all call sites is unnecessary — callers only need `createAuthedConvexClient`.
- Why not the alternatives: Keeping the Proxy forever is fine if PostHog is extracted, but Proxy remains a readability tax. Introducing a custom Convex client subclass is more code for the same behavior.
