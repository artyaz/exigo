## Decision Package — S7-B002

### Recommendation
- Approach name: **B — Shared client SSE block parser + thin per-route adapters**
- One-paragraph rationale: Three client streams in this slice reimplement buffer/split/`TextDecoder` loops with *different* wire dialects: `CourseTutor` uses proper `event:` + `data:` SSE; teach + clarify use `data:` JSON with embedded `type`. Bugs and silent swallows are easy to miss (tutor `error` event is empty). A tiny client helper that yields parsed blocks unifies readability without forcing server protocol unification in this slice (server may stay in S8).
- Why not the alternatives: A leaves three forks forever. C (normalize all server routes + one client) is correct long-term but spans S8 ownership and is larger than a clarity-first client extract.
