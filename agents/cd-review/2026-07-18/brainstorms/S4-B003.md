## Decision Package — S4-B003

### Recommendation
- **Approach name:** A — Make schema match emitted shapes; widen ObsFieldType modestly
- **One-paragraph rationale:** The schema’s job is documentation + static interface checks. Emitting `args: [5]` while declaring `args: "string"` is a liar contract. Minimal fix: add `"array"` (and optionally `"value"` for free-typed fields) to `ObsFieldType`, set `enter.args` to `"array"`, set `value` fields to `"value"` (or keep number only if probes coerce to number — they don’t). Update symbol docs if they imply string args. No runtime type enforcement required for this iteration — honesty of declarations is the north-star win; optional soft checks later.
- **Why not the alternatives:** Coerce args to JSON string at emit (B) breaks existing reactions using `at(event.args, 0)` (tests depend on array). Full runtime schema validation (C) is correctness-heavy for little authoring clarity gain right now.
