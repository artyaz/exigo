## Decision Package — S1-B006

### Recommendation
- Approach name: **One subscription resolve per auth context; type-safe internal refs; drop redundant action limits query path**
- One-paragraph rationale: `getAuthedContext` calls `getEffectiveAccessLevel` then `getEffectiveLimits`, and the latter re-calls the former — two identical `getActiveSubscription` scans per authenticated request on hot paths. Action variants use dynamic `import("./_generated/api")` + `as unknown as` + `as any` instead of static `internal.subscriptionServiceInternal.*`. `getLimits` internal query exists but action path only fetches access level and recomputes limits in process (fine) — yet the cast noise obscures a simple pattern. Fix: single helper `resolveEntitlements(ctx, userId) => { accessLevel, limits, subscription? }`; action uses `ctx.runQuery(internal.subscriptionServiceInternal.getAccessLevel, { userId })` with proper generated types.
- Why not the alternatives: Caching accessLevel on AuthedContext only without fixing getEffectiveLimits still leaves other callers double-fetching.

### Minimal implementation sketch
- Files: `convex/subscriptionService.ts`, `convex/authDecorators.ts`, `convex/subscriptionServiceInternal.ts`, maybe `crons.ts` drop `as any` if types allow.
- Steps:
  1. Add `getEffectiveEntitlements(ctx, userId)` returning `{ accessLevel, limits }` from one subscription read.

  4. Replace dynamic import in ForAction helpers with `import { internal } from "./_generated/api"`.
  5. Remove unused casts; keep getLimits internal if actions ever need full plan object.
- What NOT to do: Don't add Redis/cache layer.
