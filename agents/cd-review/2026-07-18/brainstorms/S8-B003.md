## Decision Package — S8-B003

### Recommendation
- **Approach name:** A — `requireAuthedConvex(getToken, context)` + standard public error helpers
- **One-paragraph rationale:** AGENTS.md already names the pattern: Clerk `auth()` → `createAuthedConvexClient`. A 15-line helper returning `{ userId, convex } | Response` (or throwing a typed result) deletes dozens of inconsistent catch blocks. Public JSON errors should be stable strings: `Unauthorized`, `Forbidden`, `Bad Request`, `Internal server error` — never stack/context/`err.message` from Convex. Log internals with otlp. Checkout’s public plan query can stay unauthed if the Convex query is public-by-design; if not, use internal HTTP or a public query only — **do not** pass deploy keys from client routes. generate/* should catch ConvexAuthError like learn routes.
- **Why not alternatives:** B (per-route string tweaks) does not stop drift. C (middleware-only auth) cannot create Convex clients with template tokens.

| B | Hand-fix each message string | Small diffs | Drift returns | 2/5 | S |

### Minimal implementation sketch
- Files: `src/lib/apiAuth.ts` (or extend `convexClientAuth.ts`); migrate AI routes first (hot path), then generate/*, then payments hygiene.
- Steps:
  1. `const session = await requireApiSession()` → 401 if no userId.
  2. `const convex = await requireAuthedConvex(session, context)` → 401 on ConvexAuthError, 500 opaque otherwise.
  3. `jsonError(status, code)` helper for non-stream; stream errors stay SSE.
  4. tests/chat: add userId check before Convex.
  5. feels-hard / generate/*: stop returning raw `err.message` on 500.
- What NOT to do: change webhook signature flow; add new product gates; log tokens.
