## Decision Package — S4-B002

### Recommendation
- **Approach name:** B — Split lexer/tree vs builders; error on second stage; delete dead comments
- **One-paragraph rationale:** The tokenizer/tree (`Cursor`, `parseElement`, text helpers, `validateNode`) is a pure frontend parser. The builders (`buildArena`…`buildExercise`) are IR lowering. Separating them matches the file’s own section banners and shrinks review surface. Multi-stage overwrite is a silent authoring footgun — one line of “already have a stage” error is a correctness win with almost no design space. Stale comments should die, not get new abstractions.
- **Why not the alternatives:** Full visitor framework (A) is overkill for a closed tag set; “only fix multi-stage, no split” (C) leaves the 600-line navigation tax.
