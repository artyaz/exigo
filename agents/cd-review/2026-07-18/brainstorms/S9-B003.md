## Decision Package — S9-B003

### Recommendation
- Approach name: **Fail loud on missing default key; log + structured fallback on custom-provider failures**
- One-paragraph rationale: `defaultGeminiProvider` injects `GOOGLE_GEMINI_API_KEY ?? ""`, so misconfig becomes opaque vendor 401s later. `resolveAiProvider` swallows settings-query and decrypt errors and silently returns Gemini — users who paid for/configured a custom endpoint get wrong model with no signal. Security-wise, silent decrypt failure after secret rotation is acceptable as *fallback*, but must be **observable**. Match sibling routes (`teach/route.ts`) that throw when the env key is missing.
- Why not the alternatives: Throwing on every settings fetch failure is too brittle (deploy lag). Returning empty key forever is worse.

### Approaches considered
| ID | Name | Pros | Cons | North-star score | Effort |
|----|------|------|------|------------------|--------|
| A | Throw if default Gemini key empty; log warn on settings/decrypt fallback (include reason code) | Clear failures; debuggable | Slight behavior change for missing env | 5/5 | S |
| B | Return `Result<AiProvider, ResolveError>` to all callers | Explicit | Touches every generate route | 4/5 | M |
| C | Keep silent fallbacks | No churn | Continues production footgun | 1/5 | — |

### Minimal implementation sketch
- Files to touch: `src/server/ai/resolve.ts`; optionally `ai.test.ts` for “throws without key”
- Steps:
  1. `defaultGeminiProvider`: if `!process.env.GOOGLE_GEMINI_API_KEY` throw clear Error (same text family as other routes).
  2. On settings query catch: `console.warn` or `logError` with source `server.ai.resolve`, then fallback.
  3. On decrypt catch: warn with `reason: decrypt_failed` (never log ciphertext/key), then fallback.
  4. Optional: when provider is openai but key missing, warn once instead of silent default.
- What NOT to do: Log decrypted keys or cipher material; change encryption algorithm.
