## Decision Package — S5-B002

### Recommendation
- **Approach name:** One palette module for semantic tones; Sequence/DiagramScene consume it
- **One-paragraph rationale:** Comments claim visual.ts is “the shared visual language,” but Sequence and DiagramScene each invent their own maps with **different RGB for the same tokens** (e.g. amber is `254 240 138` in shell ACCENTS, `252 211 77` in TONE_RGB, `254 240 138` in Sequence). Learners see the same “amber” tone diverge across layer types. Route Sequence and DiagramScene through `toneRgb` (or a thin hex helper built on it). Keep shell `ACCENTS` if shell accents are intentionally a separate chrome vocabulary — but document that and align numbers if they share token names.
- **Why not the alternatives:** Full design-token CSS vars rewrite is larger than the smell. Leaving three maps is the status quo debt.
