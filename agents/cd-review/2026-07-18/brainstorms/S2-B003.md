## Recommendation
- Approach name: **Explicit terminal rule + single writer for phase + phase guards on generateModule**
- One-paragraph rationale: UI renders “Course Completed!” (`page.tsx` phase === completed) but orchestrator’s `module_complete` always schedules another module; `completed` case is a no-op identity. That is a liar contract. Concurrently, `generateModule` is a public action that mutates progress without checking current phase, and actions are not transactional — double-advance can insert two modules with the same index logic based on `existingModules.length`. Minimal path: (1) define completion policy (simplest: stop after N modules constant or when AI returns empty/flag — prefer **fixed max modules** or **client “finish course” mutation** that sets completed); (2) only orchestrator (internal) mutates phase; (3) `generateModule` becomes internalAction or checks phase ∈ {module_generation} and uses conditional patch; (4) collapse duplicated module_generation / module_complete arms.
- Why not alternatives: Infinite adaptive course with no UX end is a product bug already shipped against UI. Full event-sourced state machine is overkill.
