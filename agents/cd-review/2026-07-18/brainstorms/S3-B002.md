WHAT_I_TRIED_MENTALLY: require identity.subject === args.userId or drop userId

## Recommendation
- Approach name: **A — Derive userId from auth; drop client userId args**
- One-paragraph rationale: Keep encryption at the Next.js boundary (cipher remains opaque in Convex). Make Convex refuse any operation unless `getAuthenticatedUserId` matches the row being read/written. Prefer dropping `userId` from args entirely so the only key is the Clerk subject. `getCipher` stays a public query for authenticated self only — still fine for server decrypt; useless to attackers without the app secret, but **overwrite/IDOR on settings is real** and must die.
- Why not B: checking `args.userId === identity` keeps a redundant argument that every caller can get wrong. Why not C: moving settings to Next-only storage is out of scope / feature-ish.

## Minimal implementation sketch
- Files: `convex/userSettings.ts`; callers `src/app/actions/aiSettings.ts`, `src/server/ai/resolve.ts` (other slices)
- Steps:
  1. At top of each handler: `const userId = await getAuthenticatedUserId(ctx)`.
  2. Query/patch by that `userId` only; remove `userId` from args validators.
  3. Update makeFunctionReference signatures and server actions to stop passing userId.
- What NOT to do: don't decrypt keys in Convex; don't return plaintext; don't log cipher material.
