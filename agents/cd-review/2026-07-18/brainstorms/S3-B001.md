# Decision Package — S3-B001

## Issue Packet (from L1)

```
BRAIN_ID: S3-B001
TRIGGER: security
NORTH_STAR_HURT: correct, consistent, clear
LOCATION: convex/questions.ts (entire public surface)
SYMPTOM: Public queries have zero auth; mutations trust client-supplied userId
EVIDENCE:
  - getForTest / get / getForSpace / getIncorrectForTopic never call ctx.auth
  - create / updateFeedback check space.userId against args.userId only
  - Client useQuery(api.questions.getForTest) and getForSpace without server gate
CONSTRAINTS: owned files in S3; no feature work; match authDecorators pattern
WHAT_I_TRIED_MENTALLY: require getAuthenticatedUserId + space ownership on every path
QUESTION: How to harden questions.ts with minimal, consistent auth without breaking generate/validate API routes?
```

## Recommendation
- Approach name: **A — Identity-first space ownership (drop args.userId)**
- One-paragraph rationale: Convex is the trust boundary. Every public function must derive identity from `ctx.auth` via `getAuthenticatedUserId` / `getAuthedContext`, then authorize via the question→test→space chain (or space→tests for list queries). Client-supplied `userId` is redundant and enables IDOR. API routes already pass authenticated Convex clients and the real Clerk userId; after the change they drop `userId` from mutation args. Perfect answers and feedback must not be readable without ownership.
- Why not the alternatives: B leaves a dual source of truth (`args.userId` + identity). C (make everything internal-only) would force larger Next.js refactors and break legitimate client `useQuery` for owned tests.

## Research notes
- Convex public functions are callable by any client with the deployment URL; Clerk token is optional unless checked in-handler. Server-only trust of `args.userId` is never sufficient.
- Key takeaway: Next.js Clerk `auth()` does not protect Convex public APIs.

- `default_user` exception (if retained) still widens access for any authenticated user.
