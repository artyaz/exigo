## Decision Package — S5-B001

### Recommendation
- **Approach name:** Shared sandboxed host + co-located host chrome CSS
- **One-paragraph rationale:** Open and Embed React hosts are near-forks of the same postMessage bridge (progress/complete/origin/source guards) with cosmetic class-prefix differences. Worse, the chrome that makes them readable (prox bar, frame, done chip) lives only in the playground generate page stylesheet — so `EmbedExercise` in lesson practice, collection, and atlas renders without those rules. Extract a thin `SandboxedExerciseHost` (or `useExigoFrame`) for the bridge + chrome; inject host CSS from the component tree (same inject-once pattern as `useExerciseStyles` / Commentable); keep open vs embed as thin wrappers that only differ in `build*Doc`, sizing policy (auto-height vs fixed window), and optional height/error events.
- **Why not the alternatives:** Full merge of open+embed *authoring* runtimes is a product fork (toolkit vs CDN stage) — out of scope. Copy-pasting CSS into every consumer is the current failure mode.

### Minimal implementation sketch
- Files to touch (S5 ownership): `open/OpenExercise.tsx`, `embed/EmbedExercise.tsx`, new `shell/SandboxedFrame.tsx` (or `open/_shared` — prefer shell since both use it), `shell/styles.ts` (OPEN_EMBED_CSS) **or** local inject-once beside shared host.
- Outside S5 (Phase C note): strip `.exg-open*` / `.exg-embed*` from `playground/generate/page.tsx` once co-located.
- Steps:
  1. Extract shared completion result type `FrameResult { correct?; score?; … }`.

  4. Inject host CSS once from the shared host mount.
  5. Open/Embed become ~15-line wrappers.
- What NOT to do: merge toolkits/runtimes; rewrite iframe security model; force open/embed into `ExerciseShell`.
