## Decision Package — S10-B004

### Recommendation
- Approach name: **Rename `hashId` → `maskId` (or `redactId`); apply it to convexClientAuth log attributes**
- One-paragraph rationale: `shared/hashId.ts` does not hash — it truncates with ellipsis. Call sites in payment/webhook logging rely on the name for a security expectation that is false (prefix/suffix of Paddle subscription IDs remain recoverable). Separately, `createAuthedConvexClient` logs full Clerk `sub` as `userId` on every query/mutation/action start/success/fail, contradicting the shared helper’s purpose. Fix is rename for honesty + consistent masking in Next server logs; keep the same simple mask algorithm unless product requires cryptographic redaction.
- Why not the alternatives: Real SHA-256 hashing loses correlatability that the comments intentionally preserve. Leaving the liar name is pure clarity debt. Building a full PII pipeline is YAGNI.
