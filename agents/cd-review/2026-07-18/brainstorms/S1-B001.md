## Decision Package — S1-B001

### Recommendation
- Approach name: **Delete the dead usage subsystem; keep calendar-month entity counting as the only meter**
- One-paragraph rationale: Production enforcement in `convex/tests.ts` and `convex/deepDives.ts` already counts domain rows by calendar month. The `usage` table plus `usageService` public API, `subscriptionService` test-usage helpers, and the daily `resetExpiredUsage` cron form a second, unused metering world. Public `incrementUsage` / `getUsage` / `checkUsageLimit` accept client-supplied `userId` with no auth — a live attack surface even though the app does not call them. Deleting dead public mutations + dead helpers + cron (or internalizing only if a future design needs counters) maximizes north-star brevity/clarity and closes the auth hole in one pass.
- Why not the alternatives: Wiring production to the usage table is a larger behavior change (rolling 30d vs calendar month) with no product ask; hardening-only leaves two meters forever.

### Research notes
- Convex public functions are callable by any client with the deployment URL unless the handler checks `ctx.auth`; ungated mutations with client `userId` are classic IDOR/quota-DoS vectors.
- Key takeaway: unused public API is still an attack surface.

### Residual risks

- Future feature might reintroduce counters — prefer internal mutations + auth then.
