## Recommendation

- **Approach name:** A — Delete speculative AAP surface; add one explicit adapter
- **One-paragraph rationale:** `writePolicy` and brief-level `reads`/`writes` are unimplemented speculative surface area — classic YAGNI debt that lies to readers. LessonRunner’s real contract is simpler: seed via `step.reads` at mount, commit via `step.writes` on Next/Finish. Generation should either produce that shape via a single `toLesson(draft, constructedSteps)` helper (mapping role + ReactiveSpec, no auto reads/writes) or document that generation output is not runner-ready. Do not implement writePolicy until something needs it.
- **Why not the alternatives:** B (implement full writePolicy + brief bridging) is feature work and untested product design. C (status-quo + comments only) leaves dead types that tests won’t catch.
