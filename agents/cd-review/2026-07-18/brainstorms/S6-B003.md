## Recommendation

- **Approach name:** B — Honest three-layer docs + shared extract helper; do not re-embed AUTHORING.md
- **One-paragraph rationale:** The constructor deliberately moved to markup exemplars because weak models fail on JSON-to-markup translation (file comments already state this). Re-embedding the full AUTHORING.md would fight that lesson and bloat tokens. The fix is honesty: delete or stop advertising `loadAuthoringGuide` as constructor input; retitle AUTHORING.md as *human / internal-spec* docs (or add a top banner: “not used by AI constructor”); keep AI surface as `prompts.ts` + `exemplar.ts` + `describeVocabulary`. Extract one shared `extractModelJson` (strip fences → slice first value → optional parse). Deduplicate atlas `buildSystem` against embed by calling embed builders + a short “mechanic already chosen” prefix.
- **Why not the alternatives:** A (load AUTHORING into system prompt again) regresses the weak-model thesis and duplicates exemplar content. C (delete AUTHORING.md entirely) loses valuable human recipe docs and authoring.doc.test pins.
