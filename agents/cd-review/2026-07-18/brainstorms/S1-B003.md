## Decision Package — S1-B003

### Recommendation
- Approach name: **Single plan-limits table in `shared/planConfig.ts`; strategies become thin lookups; marketing copy derived or tested against same numbers**
- One-paragraph rationale: AGENTS.md claims plan config lives in `shared/planConfig.ts`, but spaces/tests/knowledge limits are hardcoded inside three Strategy classes in `subscriptionService.ts`. Deep-dive limits alone live in `shared/`. Seed data and pricing UI advertise free "10 AI tests / month" while code enforces 3. Strategy pattern adds ceremony for a static map of three tiers. Collapse to one exported `LIMITS_BY_TIER` (or by access level) in `shared/planConfig.ts`, implement `getLimitsForAccessLevel` as a lookup, keep seed/marketing in sync via shared constants or a unit test that fails on drift.
- Why not the alternatives: Reading limits from the `plans` table would make marketing DB-editable but couples entitlement logic to display rows and breaks offline pure tests without fixtures.
