## Decision Package — S9-B002

### Recommendation
- Approach name: **Normalize on `ActionResult` + thin shared helper (learn-style base, optional code)**
- One-paragraph rationale: Four action modules implement four contracts: `knowledge` throws; `aiSettings` throws on auth and returns `{ ok: true }`; `learn` returns `{ ok, data|error }` without codes; `spaces` returns `{ ok, data|error, code }`. Callers cannot share error handling. The smallest clarity win is a single shared type + `requireUser` / `fail` helpers colocated under `src/app/actions/_result.ts` (or `src/lib/actionResult.ts`), then migrate all four modules to return `ActionResult` consistently. Prefer **spaces-style codes** only where UI already branches (`PLAN_LIMIT`); otherwise optional `code?:` keeps learn simple.
- Why not the alternatives: Keeping throws for “thin wrappers” forces every client to try/catch differently. Full RPC framework is YAGNI.
