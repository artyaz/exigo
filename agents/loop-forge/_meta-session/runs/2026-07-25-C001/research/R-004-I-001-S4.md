## Steelman (1 paragraph)
I-001-S4 makes autonomy + combinability a *runtime proof* rather than a claim. The three sub-mechanisms share one structural insight: every guarantee cd-review/brainstorm currently *assert about themselves* (no-HITL, crash-safe resume, leaf-worker contract) becomes a property loop-forge *verifies about a target loop* by running it sealed, spawning it as a worker, and killing it mid-step. This collapses verification and verification-of-verification into the same artifact (`day-status.json`) — loop-forge becomes the first exigo loop whose acceptance test IS the autonomy invariant of its product.

## Toulmin decomposition

**Claim:** A candidate `LOOP.md` can be acceptance-tested by (a) sealed canary run, (b) reverse-authority micro-cycle, (c) kill-and-resume oracle on `day-status.json`; the conjunction is sufficient to ship.

**Data:**

- D4. State-invariant oracles from state-machine diagrams are textbook. ([Offutt](https://www.albany.edu/faculty/offutt/research/papers/testOracle.pdf))
- D5. Dry-run / shadow testing = simulation without activating the actual system. ([Grokipedia](https://grokipedia.com/page/Dry_run_(testing)); [AIOps School 2026](https://aiopsschool.com/blog/shadow-deployment))

**Warrant:** If a target loop's `day-status.json` carries (state, last_step, blocked_reason, resume_hint) and a cold launcher can resume from disk after a random kill, the loop is structurally extractable + combinable — because that IS the only resume contract (D7). Runtime-verification literature (D2, D3) confirms verifying a system by running it under a stub of its environment is sound.

**Backing:** cd-review/brainstorm already trust these artifacts in production; loop-forge reuses that trust as a test oracle.

**Qualifier:** Sufficient *if* (i) the canary stub is honest, (ii) the target loop's launcher contract is spawnable without domain glue, (iii) the target emits a state machine expressible in the §0.5.4 SHAPE.

## Falsification attempt
Attack "every domain's state machine fits the cd-review §10.7 vocabulary." Read §10.7 (`work/exigo/agents/cd-review/LOOP.md:852-883`): canonical `last_step` values are `develop_pushed`, `develop_pr_open:{PR}`, `cr_poll_{N}:{PR}`, `main_merged:{PR}`, `wave_d_dispatched:{PACK}:round_{N}` — GitHub + CodeRabbit specific. A loop forged for "sort numbers" emits none of these. **Claim is literally false.** The idea conflates the §0.5.4 SHAPE (state/last_step/blocked_reason/resume_hint) with the §10.7 VALUES. Fix: canary must require the candidate LOOP.md to DECLARE its own `last_step` vocabulary; the kill-and-resume oracle runs against that declared vocabulary, not §10.7's.

Second attack (token cost): AgentGuard (D2) + \tool confirm runtime verification has nontrivial overhead, justified because a misbehaving autonomous agent in production exceeds verification cost — *if* the target loop re-runs many times. For a single-use forged loop the cost is unjustified. Qualifier needed.

## Position-swap reconciliation
Skeptic-steelman: "loop-forge verifying a target loop it itself forged is a self-licking lollipop — canary passed by construction." Reconciliation: the canary is NOT authored by loop-forge; it is a fixed stub (no human, no git, no network, wall-clock budget) authored ONCE in loop-forge's own protocol. The candidate LOOP.md does not choose the canary. The genuine circularity is the reverse-authority micro-cycle: loop-forge spawns the target with a `loop-spec.md` loop-forge wrote. If loop-forge tailors the spec to what the target already does, the test is theater. Mitigation already present in I-003-DELTA (B-003): baseline-delta-test forbids no-op compositions; same primitive applied to spec→target fit closes the loop.

## Verdict
**ADVANCE** (confidence 0.68). Each sub-mechanism is individually well-grounded in industry/runtime-verification literature and in existing repo invariants. The over-strong §10.7 vocabulary claim is a wording bug, not a structural flaw — the §0.5.4 SHAPE is the real interface. Reverse-authority circularity is the genuine open risk; mitigated but not closed by I-003-DELTA.
