## Recommendation
- Approach name: **A — Remove `default_user` ownership bypass from all S3 auth paths; treat spaces as strictly user-owned**
- One-paragraph rationale: Without a documented multi-tenant sharing model, `default_user` is a magic string that turns any space with that owner into a shared bucket for every authenticated principal. That is an authorization hole, not a feature. Strict equality `space.userId === auth.userId` matches `courses.ts` / modern paths and collapses the inconsistent matrix. If demo seeding needs sample spaces, seed them under a real test user or make them read-only via a dedicated internal query, not a public bypass.
- Why not B (formalize shared spaces): feature work. Why not C (document and keep): leaves IDOR-shaped access on knowledge + questions + chat.
