## Recommendation
- Approach name: **A — Domain functions call usageService (or shared helper) for rolling 30-day; delete calendar-month scanners**
- One-paragraph rationale: AGENTS.md and `usageService` already define the product rule (rolling 30-day). S3 reimplemented calendar-month counting with N+1 space scans (`tests`) and ad-hoc month helpers (`deepDives`). That is both wrong vs documented policy and harder to read. Prefer: on create, `check` then `increment` via usageService internals/mutations with auth; drop `getStartOfMonth*` from tests/deepDives. If usage rows are not yet written anywhere, wire increment into create paths in the same fix.
- Why not B (change AGENTS to calendar month): still leaves dead usageService and inconsistent deepDive vs tests wording ("this month"). Why not C (keep both systems): double-count risk.
