## Decision Package — S9-B006

### Recommendation
- Approach name: **Stop trusting client-supplied userId on Convex settings; authz in Convex (S3) + stop re-passing userId from actions where identity exists**
- One-paragraph rationale: `aiSettings` and `resolveAiProvider` pass `userId` into `userSettings:*` which **do not** use `getAuthedContext` / identity checks. Any authenticated Convex caller can read another user’s cipher material (`getCipher`) or overwrite settings (`save`) by swapping `userId`. Encryption keeps plaintext off Convex, but ciphertext + provider/baseUrl still enable abuse (target user → attacker’s endpoint). Fix belongs primarily in `convex/userSettings.ts` (S3): derive `userId` from auth identity; ignore or assert arg. S9 side: stop sending trust-critical userId once Convex ignores it; use `api.userSettings.*` instead of string `makeFunctionReference` if codegen is healthy.
- Why not “actions-only fix”: server actions already pass Clerk userId correctly; IDOR is on the Convex function surface callable from other clients.
