# Decision Package — S4-B008

## Issue Packet (input)
- **BRAIN_ID:** S4-B008
- **TRIGGER:** clarity + inconsistency
- **NORTH_STAR_HURT:** clarity, consistency
- **LOCATION:** `runtime/expr.ts` lexer includes `?` and `:` in punctuation set (`"+-*/%<>!()[].,?:"`) and multi includes `=>` (rejected later); parser never implements ternary
- **SYMPTOM:** Authors/models writing `cond ? a : b` get “Unexpected token” after partial parse, while `if(cond,a,b)` is the real form. Dead punctuation implies a language feature that doesn’t exist.
- **QUESTION:** Reject ternary at lex/parse with a guided error, or implement ternary?

---

## Decision Package — S4-B008

### Recommendation
- **Approach name:** B — Guided reject for `?`/`:` (and keep `if()` as the only conditional); remove dead punct if unused
- **One-paragraph rationale:** The DSL deliberately prefers closed helpers over C-style operators for control flow (`if` is already a special form). Implementing ternary (A) expands surface without necessity and duplicates `if`. Leaving silent “Unexpected token” (C) hurts model repair loops. Best: if lex sees `?` or bare `:` as operator, throw `ExprError` pointing to `if(cond, a, b)`. Optionally stop accepting `?`/`:` in the general punct set so they never tokenize as punc unless used inside strings.
- **Why not the alternatives:** Full ternary (A) fights the design. No change (C) leaves bad author errors.

### Minimal implementation sketch
- Files: `runtime/expr.ts`, `runtime/expr.test.ts`
- Steps:
  1. In lex, if ch is `?` or `:` (outside strings), throw `ExprError('Ternary `?:` is not supported. Use if(cond, a, b).')` similar to `=`.
  2. Remove `?` and `:` from the catch-all punct string.
  3. Test both forms of rejection.
- What NOT to do: implement ternary; change `if` arity.
