## Decision Package — S1-B005

### Recommendation
- Approach name: **Dedicated webhook secret + recompute accessLevel server-side from planSlug; fail closed on userId mismatch**
- One-paragraph rationale: `convex/http.ts` authorizes the Next→Convex hop with `CONVEX_DEPLOY_KEY` (deploy credential reused as shared secret). Body supplies `accessLevel` which is trusted after range check only. `subscriptionsInternal.upsertFromPaddle` logs userId mismatch against existing paddle sub but still patches entitlements onto the original owner. Money/auth path needs: (1) a purpose-built secret env (e.g. `PADDLE_CONVEX_WEBHOOK_SECRET`), (2) derive `accessLevel` from `planSlug` via shared `slugToTier`/`tierToAccessLevel` so a compromised Next process cannot invent Educator without a plan slug, (3) reject or ticket on userId mismatch instead of silent patch.
- Why not the alternatives: Full Paddle signature verification inside Convex is better long-term but duplicates Next's provider verify unless Next is removed from the path; out of S1 minimal scope to re-architect the whole webhook chain.

### Minimal implementation sketch
- Files: `convex/http.ts`, `convex/subscriptionsInternal.ts`; Next route is S8/S9 (note dependency).
- Steps:
  1. Read `process.env.PADDLE_CONVEX_WEBHOOK_SECRET` (or similar); fall back temporarily with loud error if missing in prod.
  2. On upsert: require planSlug (or look up by priceId via plans table); set accessLevel from shared mapping; ignore body accessLevel or require equality.
  3. If existing paddle sub has different userId → log + return 409 without patch (or transfer only with explicit admin flag).
  4. Align cancel path auth the same.
- What NOT to do: Log raw userIds/subscription IDs (hashId is good — keep).
