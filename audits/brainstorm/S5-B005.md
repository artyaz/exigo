## Decision Package — S5-B005

### Recommendation
- **Approach name:** Fix VM state honestly; unify inject-once helper; honest barrel
- **One-paragraph rationale:** Three separate issues that share a “host correctness / discoverability” theme. (1) `useReactiveVM` exposes `vmRef.current` as render state — it only works because `setSnapshot` re-renders after the effect; a cleaner pattern is `useState` for the VM instance (or return only snapshot/dispatch/reset and keep vm private). (2) Style injection has three patterns; extract one `injectOnce(id, css)` used by shell, comments, and the shared sandboxed host (B001). (3) Either export open/embed/comments from `index.ts` or stop claiming a single public surface — prefer thin re-exports so call sites stop deep-importing inconsistently.
- **Why not the alternatives:** Ignoring the ref pattern invites subtle tick-clock bugs if snapshot updates stop. Full CSS modules migration is too large for this iteration.

### Minimal implementation sketch
1. `useReactiveVM`: `const [vm, setVm] = useState<ReactiveVM | null>(null)` in the effect; return that.
2. `shell/injectStyles.ts`: `export function injectOnce(id: string, css: string): void`.
3. Wire `useExerciseStyles`, Commentable, sandboxed host CSS through it.
4. `index.ts`: re-export `OpenExercise`, `EmbedExercise`, `Commentable`, maybe shell types — or rewrite the header comment to list intentional deep paths.
- What NOT to do: redesign ExerciseShell prop surface in the same pack; force open/embed into shell chrome.
