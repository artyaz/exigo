## Recommendation
- Approach name: **Role-locked public sends + keep internals for AI writers**
- One-paragraph rationale: Today any authenticated lesson owner can insert `role: "teacher"` / `"system"` messages, poisoning history that teach/summarize/clarify consume. Same for tutor chats. Minimal fix: public `send` only allows `role: "user"` (hardcoded); AI/system writes go through existing `sendInternal` / `sendMessageInternal`. Next routes already use authenticated Convex client — migrate those routes (outside S2) to internal via an action, **or** temporarily keep public send but ignore client `role` and force `"user"` for client path while adding a separate internal-only path the routes call through a new server-only action. Cleanest Convex-side change: force role in public mutation; add `sendAsTeacherInternal` already present as `sendInternal`.
- Why not alternatives: Removing public send entirely breaks current routes until S8 migrates; trusting messageType without role still allows forgery.

### Minimal implementation sketch
- Files: `convex/courseLessonMessages.ts`, `convex/courseTutor.ts` (S2); follow-up S8 for routes if needed.
- Steps:
  1. Change public `send` / `sendMessage` args: drop `role` or force `role: "user"` in handler.
  2. Ensure `sendInternal` remains the only path for teacher/system/tutor.
  3. If API routes need to write teacher messages with user JWT, expose a thin **action** that runs AI then calls internal (already true for `courseAi.teachLesson`) — prefer consolidating on that path over public teacher writes.
  4. Grep: `api.courseLessonMessages.send` with role teacher/system → migrate.
- What NOT to do: Don't add complex RBAC on messages.
