## Recommendation

- **Approach name:** B — Rename + module-level README map (no product merge)
- **One-paragraph rationale:** The dual pipelines are intentional product experiments (validated markup vs free HTML embeds), but they collide on type names and mental models. Merging them is a product rewrite and violates YAGNI for a clarity pass. The north-star win is making the fork *unmissable*: distinct type names, a short map at the package roots, and stop re-exporting ambiguous aliases. Atlas should keep calling embed extraction; it should not silently re-own the embed prompt contract without saying so.
- **Why not the alternatives:** A (full unify onto markup) is large, kills free-HTML exploration, and is feature work. C (leave names, only comments) leaves `Lesson`/`LessonDraft` greppable collisions that keep causing wrong imports.

  - `generate/index.ts` / `exercises/index.ts` barrel comments

- Steps:
  1. Rename atlas `Lesson` → `AtlasLesson`, atlas `LessonDraft` → `AtlasLessonDraft` (or `MicroLessonDraft`).
  2. Rename generate `LessonDraft` stays (canonical AAP path) OR prefix `ReactiveLessonDraft` if external API already uses both — prefer atlas rename first (fewer API consumers of the type name itself; NDJSON uses structural shape).
  3. In `atlas/prompts.ts` `buildSystem`, either re-export/delegate to `embed/prompts.buildEmbedSystem` + thin “chosen mechanic” wrapper, or comment `// deliberate fork of embed: brainstorm is separate stage`.

- What NOT to do:
  - Do not merge HTML embed exercises into ReactiveSpec in this pass.
  - Do not change NDJSON event `type: "lesson"` wire shape without a compat note (rename TS types only).
