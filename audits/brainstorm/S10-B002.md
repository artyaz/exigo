## Decision Package — S10-B002

### Recommendation
- Approach name: **Collapse Next.js server PostHog to one module; keep shared AI capture separate for Convex purity**
- One-paragraph rationale: The repo currently has (1) `shared/posthogAiObservability.ts` fetch-based client for Convex+Next AI events, (2) `src/lib/posthog-server.ts` `getPostHogServer()` which is **never imported**, (3) a second `posthog-node` singleton inside `src/lib/convexClientAuth.ts`, and (4) yet another one-shot `PostHog` in root `instrumentation.ts`. That is four shapes for the same product analytics backend. North star wants one readable server path on Next and one pure shared helper for cross-runtime AI events.
- Why not the alternatives: Forcing Convex to use `posthog-node` breaks the Convex runtime (Node package). Merging AI event helpers into `src/lib` would break Convex imports (`shared/` boundary). Full observability gateway rewrite is YAGNI.

### Minimal implementation sketch
- Files to touch (S10): `src/lib/posthog-server.ts`, `src/lib/convexClientAuth.ts`; note for orchestrator: root `instrumentation.ts` is outside S10 ownership for Phase D unless pack expands.
- Steps:
  1. Flesh out `getPostHogServer()` to soft-fail (return null) when key missing — match OTLP/shared null pattern, not throw — so callers can no-op.
  2. Replace `getConvexPosthogClient` / `ensureConvexPosthogClient` in `convexClientAuth.ts` with `getPostHogServer()`.
  3. Leave `shared/posthogAiObservability.ts` as the only fetch-based client (Convex-safe). Document in a one-line file comment: “Convex + Next AI events only; not for general product analytics.”
  4. Do not move `NEXT_PUBLIC_*` reads out of shared without Convex env redesign (see residual).
- What NOT to do: Do not import `posthog-node` from `shared/`. Do not invent a third abstraction layer.

### Research notes
- Sources: PostHog Node SDK singleton guidance; Exigo AGENTS.md dual-runtime `shared/` rule.
- Key takeaway: Two runtimes legitimately need two transports (fetch vs posthog-node), but **three** Next-side node clients are pure mud.

### Residual risks
- `getPostHogServer` currently throws — changing to null may surprise future callers; only one dead export today.
- Shared module still uses `NEXT_PUBLIC_POSTHOG_*` which must be set on Convex deployment for AI events to fire; silent no-op is intentional but easy to miss in prod.
