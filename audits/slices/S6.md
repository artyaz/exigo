## Findings

### F-S6-001 · P1 · structure / consistency

**Title:** Two generation pipelines share “lesson/exercise” language but emit incompatible artifacts  

**Location:** `generate/**` vs `atlas/**` (+ API consumers outside slice)  

**Evidence:**
- `generate` path: structured `ExerciseBrief` → markup → validated `ReactiveSpec` (`constructExercise`).
- `atlas` path: free-form string descriptions → brainstorm mechanic → HTML body (`extractEmbedHtml`), rendered in `EmbedExercise`.
- Colliding type names:
  - `generate/brief.ts` `LessonDraft` = steps of role + ExerciseBrief  
  - `atlas/prompts.ts` `LessonDraft` = `{ title, content, exercises: string[] }`  
  - `atlas/types.ts` `Lesson` = markdown lesson + specs  
  - `lesson/types.ts` `Lesson` = ReactiveSpec steps + lessonState  

**North-star harm:** A competent engineer cannot tell which “lesson generator” is canonical; grepping `Lesson`/`LessonDraft` is archaeology.  

**Minimal fix:** Approach **B** from brainstorm — rename atlas types (`AtlasLesson`, `AtlasLessonDraft`), add package-header maps that name both pipelines and their outputs; do not merge products.  

**Effort:** S  
**Test plan:** typecheck; atlas unit tests; spot-check imports.  
**Brainstorm:** `audits/brainstorm/S6-B001.md`

### F-S6-002 · P1 · structure / clarity

**Title:** LessonRunner and generate pipeline do not share a real contract (writePolicy vapor, no assemble)  

**Location:** `lesson/types.ts`, `lesson/LessonRunner.tsx`, `generate/lesson.ts`, `generate/brief.ts`  

**Evidence:**
- `LessonWritePolicy` / `writePolicy` defined only in `lesson/types.ts`; never read.
- `LessonRunner` commits `writes` only on Next/Finish; `attempts` hardcoded to `1`; ignores policies.
- `constructLessonExercises` returns `ConstructedStep[]` (`role`, `brief`, `result`) — not `lesson/types.Lesson`.
- `ExerciseBrief.reads` / `writes` exist on the schema but never appear in prompts, constructor, or runner assembly.
- Header comment in `types.ts` presents AAP §4 as if implemented.

**North-star harm:** False abstraction boundary; generation output cannot be fed to the only lesson UI without ad-hoc glue the codebase never provides.  

**Minimal fix:** Approach **A** from brainstorm — delete unused `writePolicy` and unused brief `reads`/`writes` (or stop advertising them); add pure `assembleLesson(draft, steps) → Lesson` for ok constructions; align runner comments/meta with commit-on-Next reality.  

**Effort:** S–M  
**Test plan:** unit test `assembleLesson` skips failed steps; existing runner smoke if any.  
**Brainstorm:** `audits/brainstorm/S6-B002.md`

### F-S6-003 · P1 · clarity / inconsistency

**Title:** AUTHORING.md and `loadAuthoringGuide` claim to drive the constructor; prompts never load them  

**Location:** `generate/guide.ts`, `generate/prompts.ts`, `AUTHORING.md`, `generate/index.ts`  

**Evidence:**
- `guide.ts` comment: “Loads AUTHORING.md … so the constructor prompt and the human-facing docs never diverge.”
- `loadAuthoringGuide` is only exported; zero call sites in construction.
- Actual constructor system = `describeVocabulary()` + `NOCODE_EXEMPLAR` + `MARKUP_EXEMPLAR` (`prompts.ts` / `exemplar.ts`).
- `AUTHORING.md` opens with “written to be embedded in a generator model's prompt” and is ~90% **JSON** ReactiveSpec recipes, while the AI is required to emit **markup**.

**North-star harm:** Liar documentation; maintainers “fix the guide” believing models will see it; dual sources of truth with no link.  

**Minimal fix:** Approach **B** from brainstorm — delete dead `guide.ts` export; retitle AUTHORING as human/internal-spec doc (not constructor input); keep AI surface as prompts + exemplars + manifest vocabulary.  

**Effort:** S  
**Test plan:** `authoring.doc.test.ts` still passes; optional assert banner phrase.  
**Brainstorm:** `audits/brainstorm/S6-B003.md`

### F-S6-005 · P2 · consistency / brevity

**Title:** Atlas `buildSystem` re-forks embed constructor system prompt  

**Location:** `atlas/prompts.ts` `buildSystem`/`buildUser` vs `embed/prompts.ts` `buildEmbedSystem`/`buildEmbedUser`  

**Evidence:** Both inject `STAGE_MANIFEST` + `DESIGN_SYSTEM` and the `Exigo.complete` contract. Embed does in-prompt brainstorm (2–3 mechanics); atlas does separate brainstorm stage then `buildUser(description, mechanic)`. Near-duplicate long strings will drift.  

**North-star harm:** Two “author HTML exercise” prompts to maintain; atlas/embed inconsistency on design rules.  

**Minimal fix:** Implement atlas build as “embed system + one-line prefix that mechanic is pre-chosen” (or shared core body function). Keep separate brainstorm stage.  

**Effort:** S  
**Test plan:** string-contains key contract phrases; manual one-shot build optional.  
**Brainstorm:** `audits/brainstorm/S6-B001.md` + `S6-B003.md`

### F-S6-007 · P2 · correctness / clarity (runner)

**Title:** LessonRunner silent failure modes and incomplete step meta  

**Location:** `lesson/LessonRunner.tsx`  

**Evidence:**
- `seedExercise` / `commitWrites` swallow all `run()` errors (empty catch).
- If user hits Next before any snapshot (`snapRef.current` null), writes are skipped silently — lessonState may not update.
- `attempts: 1` always; duration resets per step but attempts never tracked.
- Finish screen dumps raw `JSON.stringify(lessonState)` with no empty-state copy when nothing was written.
- ROLE_LABEL maps `reveal` → “Observe” while file comment says “Predict → Observe → Explain → Apply” but roles include prime/name/stretch/reflect.

**North-star harm:** Harder to debug lesson bridging; silent data loss on bad exprs.  

**Minimal fix:** Document swallow-as-default; at least surface dev-only warn; track attempts from snapshots if ReactiveExercise exposes them; fix header comment to list real roles. Do not implement full writePolicy (see F-S6-002).  

**Effort:** S  
**Test plan:** pure unit tests for seed/commit if extracted.  
**Brainstorm:** `audits/brainstorm/S6-B002.md` (clustered); residual runner polish is L2-skippable once contract is fixed.

## Patterns

1. **Forked products, shared nouns** — markup/Reactive vs HTML embed; three meanings of “Lesson”.
2. **Speculative AAP surface** — types ahead of implementation (`writePolicy`, brief reads/writes).
3. **Liar comments / dead loaders** — `loadAuthoringGuide`, AUTHORING “embedded in prompt”.
4. **LLM extract helpers proliferate** — fence strip copied per pipeline with different edge cases.
5. **Good local craft inside generate** — repair loop, markup-vocab error rewrite, exemplar playability tests are strong; mud is at *boundaries between packages*.
