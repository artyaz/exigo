## Findings

### F-S5-001 — P1 — bug / consistency  
**Title:** Open/Embed host chrome CSS lives only on playground generate page  
**Location:** `src/app/playground/generate/page.tsx` (~102–113); consumers `LessonPractice.tsx`, `playground/collection/page.tsx`, `atlas/AtlasExplorer.tsx` use `EmbedExercise` without that CSS  
**Evidence:** Grep shows `.exg-embed*` / `.exg-open*` defined solely in generate page; `EmbedExercise` / `OpenExercise` reference those classes but never inject styles (unlike `useExerciseStyles` / Commentable).  
**North-star harm:** Correctness (unstyled progress/done/frame outside one page) + consistency (shell owns CSS; these hosts don’t).  
**Minimal fix:** Co-locate host chrome CSS with the shared host (or inject-once from Embed/Open). Remove orphans from generate page.  
**Effort:** S  
**Test plan:** Mount EmbedExercise outside generate page; assert prox/done classes present and styles node injected.  
**Brainstorm:** `audits/brainstorm/S5-B001.md`

## Patterns

1. **Dual AI sandbox products (open vs embed)** intentionally differ in toolkit vs CDN stage / auto-height vs fixed window — keep product dual; **do not** keep dual *host React* or dual *extract* helpers.
2. **“Models not pixels” display layers** are strong (Arena/Plot/Graph + visual.ts) but undermined by local tone maps and eval glue scatter.
3. **Inject-once CSS** is the house pattern for exercise chrome; open/embed forgot it.
4. **Sibling inconsistency is the main smell**, not missing features: Graph unique markers vs Arena fixed id; embed type naming vs open collision.
5. **Public barrel is aspirational** — real UI imports deep paths.
