### F-S1-001 — P0 — security
**Location:** `convex/usageService.ts` L12–106 (`getUsage`, `incrementUsage`, `checkUsageLimit`)

**Evidence:** All three public Convex functions take `userId: v.string()` from the client and never call `ctx.auth` / `getAuthedContext`. Grep shows **zero app call sites** for these APIs — only the generated API types and this file. Production still exposes them on the deployment.

```35:48:convex/usageService.ts

    // ...
```

**North-star harm:** Correctness/security first on money-adjacent quotas; also clarity (dead public surface). Anyone with the Convex URL can inflate another user's counter or read usage without auth.

## Patterns

1. **Documented architecture ≠ running architecture** — AGENTS usageService + planConfig + withAuth all partially false.
2. **Dual / triple implementations** — metering (usage table vs calendar counts), auth helpers (soft vs hard), plan queries (three APIs), limit numbers (code vs seed vs pricing).
3. **Dead public Convex surface** — callable, untested, ungated (`usageService`).
4. **Ceremony without consumers** — Strategy OO, `withAuth` HOF, health VERSION.
5. **Tests that freeze fiction** — limitEnforcement reimplements wrong world (privateMetadata plan, per-space test counts).
6. **Money path soft-fails** — userId mismatch warn+patch; accessLevel from caller integer.
7. **`as any` on internal refs** — crons + action entitlement path.
