## Findings

### F-S10-001 — Incomplete middleware protection for session-owned routes
- **Severity:** P1  
- **Category:** security / consistency  
- **Location:** `src/middleware.ts:3–7`  
- **Evidence:**  
  ```ts
  const isProtectedRoute = createRouteMatcher(['/spaces(.*)', '/tests(.*)']);
  // …
  if (isProtectedRoute(req)) await auth.protect();
  ```  
  Product UI under `/settings` (AI provider keys via server actions), `/knowledge-nodes`, `/checkout`, `/playground` is not edge-gated. Server actions call `auth()`, but the pages themselves render for signed-out users; `/spaces` would not. AGENTS.md documents middleware as the product gate.  
- **North-star harm:** Clarity (middleware is a partial truth) + correctness/security (inconsistent auth surface).  
- **Minimal fix:** Expand matchers per L2 recommendation A.  
- **Effort:** S  
- **Test plan:** Signed-out navigation to `/settings` and `/knowledge-nodes` redirects like `/spaces`; `/pricing`, `/`, `/terms` stay public.  
- **Brainstorm:** `audits/brainstorm/S10-B001.md`

### F-S10-002 — PostHog client sprawl (dead module + private twin + shared fetch)
- **Severity:** P1  
- **Category:** inconsistency / brevity  
- **Location:** `src/lib/posthog-server.ts` (entire file, **zero importers**); `src/lib/convexClientAuth.ts:57–108`; `shared/posthogAiObservability.ts:32–62`  
- **Evidence:**  
  - `getPostHogServer()` is never imported anywhere in the repo.  
  - `convexClientAuth` maintains a private lazy `posthog-node` singleton (`ensureConvexPosthogClient`).  
  - Shared AI observability uses a third transport (raw `fetch` to `/capture/`).  
  - Root `instrumentation.ts` (outside slice but sibling pattern) constructs yet another one-shot `PostHog`.  
- **North-star harm:** Readability and consistency — four ways to talk to PostHog; one is dead.  
- **Minimal fix:** Make `posthog-server` the sole Next `posthog-node` entry; wire `convexClientAuth` to it; keep shared fetch client for Convex purity.  
- **Effort:** M  
- **Test plan:** Missing env still no-ops; with env set, Convex client failures still call `captureException`; AI `$ai_generation` still fires from shared helper.  
- **Brainstorm:** `audits/brainstorm/S10-B002.md`

### F-S10-003 — Dead tRPC scaffolding still wraps the entire app shell

### F-S10-004 — Liar `hashId` + full Clerk user ids in Convex HTTP client logs
- **Severity:** P2  
- **Category:** clarity / security (PII in logs)  
- **Location:** `shared/hashId.ts:1–10`; `src/lib/convexClientAuth.ts:151–176`  
- **Evidence:**  
  ```ts
  /** Masks an identifier… */
  export function hashId(id: string): string {
    if (id.length > 8) return `${id.slice(0, 4)}...${id.slice(-4)}`;
  ```  
  Name says hash; body is prefix/suffix mask. Meanwhile operation logs emit **unmasked** `userId: distinctId` on every start/success/fail of proxied Convex calls — high volume, third-party OTLP.  
- **North-star harm:** Clarity (liar name); consistency with payment paths that already call `hashId`; correctness of privacy expectations.  
- **Minimal fix:** Rename → `maskId`; mask OTLP `userId` attributes; keep raw distinctId for PostHog product analytics.  
- **Effort:** S–M (rename fans out to convex)  
- **Test plan:** Unit test mask shapes; log attrs redacted; PostHog exception still receives real distinct id.  
- **Brainstorm:** `audits/brainstorm/S10-B004.md`

### F-S10-005 — `convexClientAuth` multi-concern module (auth + Proxy telemetry + private PostHog)
- **Severity:** P2  
- **Category:** structure / readability  
- **Location:** `src/lib/convexClientAuth.ts` (~195 lines)  
- **Evidence:** Single module: custom error, base64 JWT peek, dual PostHog helpers, OTLP start/success/fail, and a `Proxy` intercepting `query`/`mutation`/`action`. Public API (`createAuthedConvexClient`) is good and widely used; internals require archaeology.  
- **North-star harm:** Readability on a hot path (every AI route and server action).  
- **Minimal fix:** After B002, extract PostHog; keep Proxy only if method binding requires it; otherwise wrap three methods explicitly. Do not change caller signature.  
- **Effort:** M  
- **Test plan:** Authed query/mutation still works; auth errors still throw `ConvexAuthError`; failures still rethrow after log.  
- **Brainstorm:** `audits/brainstorm/S10-B005.md`

### F-S10-006 — Dead / divergent Clerk appearance module

### F-S10-007 — `env.js` is paper safety; app reads `process.env` directly
- **Severity:** P2  
- **Category:** consistency / clarity  
- **Location:** `src/env.js`; contrast `src/lib/convexClientAuth.ts`, `src/lib/posthog-server.ts`, `src/lib/otlpLogger.ts`, `ConvexClientProvider.tsx`  
- **Evidence:** t3 `createEnv` schema exists and requires `DATABASE_URL` (legacy Prisma). Almost no product code imports `~/env` (only `src/server/db.ts` and tRPC route). Critical vars (`NEXT_PUBLIC_CONVEX_URL`, Gemini keys, PostHog, Paddle) are read raw. Schema marks many production secrets optional, so validation does not enforce the real contract.  
- **North-star harm:** Clarity — engineers think env is validated; runtime still surprises. Brevity — dual sources of truth.  
- **Minimal fix (surgical):** Either (1) route S10 lib modules through `env` for vars already in schema, or (2) document that `env.js` is Prisma/tRPC-only and stop growing it until product migrates. Prefer (1) for Convex URL + PostHog public keys used by shell/lib. Soften `DATABASE_URL` requirement when Prisma is not on critical path (coordinate with S9).  
- **Effort:** M  
- **Test plan:** `SKIP_ENV_VALIDATION=1` build still works; missing Convex URL still fails loudly in provider/client.  
- **Brainstorm:** L2 skipped: cluster with B003 scaffold cleanup; decision is use-or-scope, not multi-option redesign.

### F-S10-009 — Shared AI observability silently depends on Next-public env names in Convex
- **Severity:** P2  
- **Category:** structure / boundary clarity  
- **Location:** `shared/posthogAiObservability.ts:34–61`  
- **Evidence:** `getPosthogClient()` requires `process.env.NEXT_PUBLIC_POSTHOG_KEY` and `NEXT_PUBLIC_POSTHOG_HOST`. Module is imported heavily from `convex/*` (actions/nodes/messages). If Convex deployment only sets non-`NEXT_PUBLIC_` secrets, AI analytics silently no-op (`.catch(() => undefined)` on fetch). Name `NEXT_PUBLIC_` implies browser bundle, not Convex backend.  
- **North-star harm:** Clarity of ops contract; consistency with server `POSTHOG_PROJECT_TOKEN` used by OTLP.  
- **Minimal fix:** Read `POSTHOG_PROJECT_TOKEN ?? NEXT_PUBLIC_POSTHOG_KEY` (and host equivalents) inside shared helper; one-line comment that Convex must set the same key; do not import `src/`.  
- **Effort:** S  
- **Test plan:** With only server token set, capture still attempts; without any key, no-op.  
- **Brainstorm:** Clustered under B002 (observability consolidation); no separate brain file.

## Patterns

1. **Scaffold residue in the shell** — tRPC provider, T3 metadata, mostly-unused `env.js` / Prisma `DATABASE_URL`, dead PostHog helper. Real system is Convex + Clerk + Gemini; shell still half-T3.  
2. **Observability multipolar** — OTLP logs, PostHog JS client, posthog-node × N, shared fetch capture; no single mental model.  
3. **Auth edge list under-specified** — middleware whitelist of protected prefixes lags product surface area.  
4. **shared/ purity is mostly healthy** — plan config, topic requests, insertion planner, subscription statuses are pure and tested. Main boundary smell is env naming for analytics.  
5. **Naming honesty gaps** — `hashId` does not hash; `UNLIMITED_LIMIT = Infinity` coexists with `MAX_TESTS_SENTINEL` (documented but easy to misread).  
6. **Style/token split is intentional and good** — `exigo-tokens.css` + utilities in `globals.css`; lesson CSS is large but domain-cohesive (not mixed with React).  
7. **Indentation drift** — `shared/` and some lib files use 2-space; `bulkImportParser` / `clerk-shared` / `convexClientAuth` use 4-space. Polish only.
